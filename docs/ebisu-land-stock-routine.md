# Claude ルーティン設定（恵比寿 物件在庫）

毎朝の配信は **Apps Script の自動メール**（`sendLandStockMail`）で行います。
設定手順は `docs/ebisu-land-stock-quickstart.md` の「7. 毎朝のメールを設定する」を参照してください。

このファイルは、そのうえで **Claude にも報告や月次のふりかえりをさせたい場合**の設定です。
メールだけで足りるなら、ここは設定しなくて構いません。

## 毎朝の報告（任意）

メールとは別に、この会話にも状況を出したい場合に設定します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 22 * * *` |
| 対応する日本時間 | 毎日 7:00 |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |

cron は UTC で書きます。日本時間 7:00 は UTC 22:00 で日付が前日に戻ります。
メールと同じ時刻にすると二重になるので、時刻をずらすか、どちらか一方にしてください。

### ルーティンのプロンプト

社内情報（スプレッドシートID）は伏せています。実際のルーティンには実値を入れて登録してください。

```text
【定期実行】恵比寿の物件在庫チェックの時間です。この会話で決めた手順どおりに実行してください。

1. Google Drive の read_file_content で fileId `<LS_SPREADSHEET_ID>`（「恵比寿 物件在庫」）を読む。
2. 「日次サマリ」から本日（JST）の行を取り出す。無い場合は最新日の行を使い、
   何日ぶんの遅れかを明記する。
3. 次の内容を、この会話に報告する（メール送信・外部投稿はしない）。
   ・いまの在庫：合計と、土地／戸建／アパート／ビル／マンション(区分)の内訳、前日比
   ・当日の動き：新規・掲載終了・値下げ
   ・今月の動き：「月次サマリ」の当月行から、月初在庫・新規・掲載終了・月末在庫・平均掲載日数
   ・月次の推移：直近6か月の掲載終了件数（種別ごと）と月末在庫。増えているか減っているかを一言で
4. 「取込ログ」の最新行を見て、当日の取込行数が0だった場合は
   「本日の収集が入っていないため、掲載終了の判定は止まっています」と先頭に書く。
5. 気づいた変化（在庫が前日比で大きく動いた／特定の種別だけ掲載終了が続いている／
   値下げが増えている）があれば、数字を添えて2〜3行で指摘する。
6. 数字はシートの値をそのまま使い、推測で補完しない。読めない場合は原因を報告して終了する。

「掲載終了」は成約と取下げの合計であり、成約件数そのものではない点を毎回明記すること。
このデータは社外秘。外部サービスへ投稿したり、指示なくメール送信したりしないこと。
```

## 月1回：成約実績の答え合わせ（任意）

国交省の取引価格情報は四半期ごとの公表なので、月1回で足ります。
Apps Script のトリガー（時間主導型 / 月ベース）で `fetchEbisuTrades` を実行してください。

Claude 側で月次のふりかえりをさせる場合のプロンプト例：

```text
【定期実行】恵比寿の月次ふりかえりです。

1. Google Drive の read_file_content で fileId `<LS_SPREADSHEET_ID>` を読む。
2. 「月次サマリ」から直近12か月を取り出し、種別ごとの掲載終了件数の推移を表にする。
3. 「成約実績・四半期」があれば、同じ期間の実際の成約件数・中央値価格・中央値坪単価を並べ、
   掲載終了件数とのズレを示す。国交省の公表は4〜5か月遅れるため、
   直近の四半期はまだ数字が出そろっていない点を明記する。
4. 在庫の増減、はけるまでの平均掲載日数、価格帯の動きについて、傾向を5行以内でまとめる。
5. 数字はシートの値をそのまま使う。外部送信はしない。
```

## 運用メモ

- 掲載終了日は「最後に掲載を確認できた日」で記録するため、直近数日の数字は後から増えます。
  確定した数字が欲しいときは、月が変わってから月次サマリを見てください。
- 収集が飛んだ日があると判定がずれます。取込ログで毎日入っているか確認してください。
