# 朝の出社メンバー一覧メール（設計メモ）

毎朝、その日の「誰が何時から出社か」を一覧にしてメールで受け取るための設計。

## 結論：既存のデータだけで実現できる

新しい連携を作らなくても、いま揃っている3つの情報源で組み立てられる。

| 情報源 | 何が分かるか | 読み方 |
| --- | --- | --- |
| 勤務表スプレッドシート（下期・月別シート） | **勤務区分と時間帯**（S / S2 / A / B / C / 横浜A・B / 休み / ✖ / 有休 など） | Google Drive の read_file_content |
| サイボウズ Office（Googleカレンダーに取り込み済み） | **当日の予定**（外出・来客・面接・在宅・出張など）と参加者 | Google Calendar の list_events |
| Google カレンダー（本人分） | 個人予定の補足 | 同上 |

サイボウズは Google カレンダーへ取り込み済みのため、サイボウズ側の API 連携は不要。
カレンダーIDは実行環境側（ルーティン設定）で管理し、このリポジトリには置かない。

## 勤務区分から出社時刻を出す

勤務表の「設定」シートの勤務記号マスタがそのまま変換表になる。

| 記号 | 時間帯 |
| --- | --- |
| S | 10:00〜18:00 |
| S2 | 11:00〜19:00 |
| S3 | 12:00〜20:00 |
| A | 10:00〜15:00 |
| B | 13:00〜18:00 |
| C | 10:30〜15:30 |
| 横浜A / 横浜B | 横浜支店（10:00〜15:00 / 13:00〜18:00） |
| F | 在宅勤務 |
| 休み / ✖ / 有休 / 半休 / 特休 / 代休 / 夏休 / 冬休 / 欠勤 | 出社なし |
| フレックス / 時間指定 | セルまたは備考欄の記載をそのまま使う（例：`13時〜16時`、`10～13`） |

- 各メンバーは2行組で、**上段が勤務区分・下段が備考欄**。備考に時刻が書かれていたら備考を優先する。
- 当社休日は水曜・日曜。
- 記号を勝手に推測で補完しない。読めない場合はその旨をメールに明記する。

## 予定の重ね方

カレンダーの件名の接頭辞で扱いを変える。

| 接頭辞 | 扱い |
| --- | --- |
| `外出:` | 出社しているが不在の時間帯として併記 |
| `来客:` `面接:` | 在席が必要な予定として併記 |
| `在宅` を含むもの | 出社ではなく在宅として扱う |
| `やること:` | 出さない（定例のタスク置き場のため） |
| `重要:` | 終日・複数日にまたがる通達枠は出さない。時刻が入っている単発の予定は出す |

参加者は本文の `■参加者` 行から取る。日付だけの終日予定は時刻を出さず「終日」と表記する。

## メール本文の形

```
件名：【本日の出社予定】2026年9月7日(月)　出社7名

小林様　お世話になっております。
本日の出社予定です。

■ 出社（7名）
11:00〜19:00  小林敏     10:00 藤沢土木事務所／13:00 外出（ベンツ藤沢）／16:00 来客
10:00〜18:00  森比査子   11:30 来客（司法書士）／13:30・15:00 面接
10:00〜18:00  久世宏美   13:30・15:00 面接
10:30〜15:30  島田詠巳   13:30・15:00 面接
10:00〜15:00  永裕子     13:30・15:00 面接
10:00〜15:00  松戸実治
13:00〜18:00  佐々木卓也

■ 在宅
（なし）

■ 休み
廣石浩／柳原千鶴（公休）／相澤圭亮／居松將司

※ 勤務表と サイボウズ の予定から自動作成しています。
```

## 実装方式

既存の「営業日報まとめメール」と同じ2段構え。

1. **Claude のルーティン**（まずはこちら）
   平日の朝にセッションを起こし、上記の手順で集計して送信する。
   勤務表の書式変更に強く、すぐ始められる。
2. **Google Apps Script**（恒久運用に切り替える場合）
   `CalendarApp` と `SpreadsheetApp` で同じ処理を行い、時間主導トリガーで送信する。
   セル位置に依存するため、勤務表のレイアウトが固まってから作る。

## 注意点

- **サイボウズの取り込みには時間差がある。** Googleカレンダー側の iCal 取り込みは数時間おきに更新されるため、
  当日の朝に急遽入った予定は朝のメールに載らないことがある。本文に取り込み時刻を明記する。
- 勤務表が翌月分まで埋まっていない場合は「勤務表が未入力」と明記し、推測で埋めない。
- 祝日行は勤務表の「祝日・行事」行から取れる。
- 社内の氏名・スプレッドシートID・カレンダーID・宛先は、このリポジトリには置かない。

## 決定した運用

| 項目 | 決定 |
| --- | --- |
| 配信タイミング | **毎日 18:00（JST）**、翌日分 |
| 宛先 | 通常営業日＝小林・森（常に）＋翌日が出社または在宅の全員／定休日・祝日・連休＝その日に勤務が入っている人だけ／勤務者0人＝送信なし |
| 送信の形 | **1人1通の個別送信**（cc・bccは使わない） |
| 個人欄 | 各メールに本人だけの「今月ここまでの勤務日数／今月の予定／残り」を記載 |
| 送信方法 | 自動送信 |
| 実装 | Claude のルーティン。設定は `docs/attendance-routine-prompt.md` |

前夜に配ることで、翌日の人員を見てから帰れる。翌日の勤務者本人にも届くので、
各自が「明日は誰がいるか」を前夜に把握できる。

**曜日で休みを判断しない。** 定休は水曜・日曜だが、祝日・シルバーウィークを含め、
休業日でも勤務が入っている人がいる。その日は勤務者だけに送る。

**個人の勤務日数は本人にしか見せない。** そのために1人1通に分けている。
名簿部分は全員共通で、個人欄だけが差し替わる。

在宅の内訳は出せない。勤務表は在宅の日も S や C のまま記録されており
（例：9/8の森さんは在宅だが勤務表は S）、在宅かどうかはサイボウズ側にしかないため。

# 朝礼・夕礼の当番制（2026年10月〜）

2026/10/5 の夕礼が「誰も始めると言わないまま」流れたことをきっかけに導入。

## 当番表（曜日固定＋例外）

| 曜日 | 朝礼 10:00〜10:30 | 夕礼 17:30〜18:00 |
| --- | --- | --- |
| 月 | 若手A（相澤に相当する社員が出社した日はその社員） | 午後要員A |
| 火 | 役員B（在宅・WEB参加・**固定**） | 第2・第4＝代表／第1・第3・第5＝管理担当 |
| 木 | 管理職C（在宅・WEB参加・**固定**） | 午後要員B |
| 金 | 時短社員D（同上の例外あり） | 午後要員A×3・管理担当×1・時短社員D×1 |
| 土 | 管理担当（月1回だけ役員B） | 土曜要員A×3・土曜要員B×2 |

水曜・日曜は定休のため当番なし。全員休みの日も当番なし。

## 配分の指定（代表の指示）

代表5%・役員B 5%・土曜要員B 10%（※実際は土曜のみ勤務のため5%が上限）・管理担当15%・
相澤相当は出社日すべて・土曜要員Aは土曜の半分・残りは均等割。

## 運用ルール

- 正当番が休み・公休・欠勤、または勤務時間が10:00／17:30を含まない日は、
  **その日に在席している人へ自動で振り替える**。勤務表には振替後の実際の担当者を書く。
- 当番は「朝礼（夕礼）始めます」と声をかけるだけ。全員揃っていなくても時間になったら始める。
- 火曜・木曜の在宅固定は、在宅でもWEBで朝礼に出るため成立する。

## 勤務表への記載

各月シートの「勤務人数」行の1行下から2行、`朝礼当番 10:00` / `夕礼当番 17:30` を追加し、
日付列に `●氏名` を**赤字・太字・薄い赤背景**で記入する。その2行下に凡例を入れる。
既存の行は絶対に上書きしない（空き行だけを使う）。

## 毎月の約束（重要・代表との取り決め）

**毎月26日 16:47（JST）に自動で起動し、翌月の当番プランを作って代表にメールで確認する。**

1. 翌月シートの勤務表を読む。未入力なら「まだ入力されていません」と知らせて終了。
2. 上記ルールで日別の当番を割り当てる。
3. **代表1人だけに**「【ご確認】◯月の朝礼・夕礼 当番プラン」を送る。
   日別当番表／1人あたりの回数と比率／ルールどおりにできなかった日と理由／
   「よろしければ勤務表への書き込みと全員配信を行います」を入れる。
4. **代表の承認が出るまで、勤務表には書き込まない。全員にも配信しない。**
5. 承認後に、勤務表へ記載 → 全員へ1人1通で配信。

この手順は代表との約束事であり、勝手に省略・変更しない。
