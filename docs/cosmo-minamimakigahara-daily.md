# コスモ南万騎ヶ原 1st PLACE 日次マーケットレポート

対象住戸の販売状況・同マンション/近隣の成約・新規売出を、毎日 15:00（JST）に
担当者へメール配信するための運用仕様です。

※ 物件所在地・住戸番号・関係者名・宛先アドレスなどの社内情報はこのリポジトリには
置かず、実行環境側（Claude のルーティン設定）で管理します。

## 配信仕様

| 項目 | 内容 |
| --- | --- |
| 配信タイミング | 毎日 15:00（JST）＝ cron `0 6 * * *`（UTC） |
| 宛先 | 社内担当者1名＋提携先担当者1名（設定値として管理） |
| 件名 | `【コスモ南万騎ヶ原 日次レポート】YYYY年M月D日(曜)` |
| 送信方法 | 自動送信 |

## レポート構成

1. **自社物件の現況** — 売出価格・面積・間取り・階・向き・販売日数・直近の価格変更からの経過日数
2. **今月の成約** — 同マンションおよび近隣競合の成約（価格・面積・間取り・階・販売日数）
3. **新規売出** — 前回配信以降に新規で市場に出た住戸（価格・面積・間取り・特徴）
4. **ライバル物件一覧** — 同価格帯／同面積帯の競合を表で比較
5. **所見** — 価格ポジション、値下げ判断の目安、次アクション

## データソースと制約（重要）

| 情報 | 一次ソース | 本自動化からの取得可否 |
| --- | --- | --- |
| 自社物件の売出状況 | 媒介会社の販売報告／自社管理 | ✕（手入力・共有が必要） |
| 成約事例 | REINS（宅建業者専用） | ✕（会員ログインが必要） |
| 新規売出・競合 | SUUMO / HOME'S / at home / 媒介会社サイト | ✕（実行環境の外部アクセス制限で遮断） |
| 参考相場・市況 | Web検索 | △（要約のみ。鮮度・精度に限界あり） |

Claude の実行環境からは不動産ポータルおよび REINS へ直接アクセスできません
（組織のエグレスポリシーによる遮断）。そのため**成約情報と新規売出情報は、
下記いずれかの方法で自動化側にデータを渡す必要があります。**

### 採用した方式：スプレッドシート ＋ Web検索の併用

- **一次ソース：** 専用スプレッドシート「コスモ南万騎ヶ原 マーケットデータ」。
  REINS の成約事例、媒介会社からの販売報告、競合の売出状況をここに転記します。
  配信時にこのシートを読み取って ②今月の成約 と ③新規売出 を構成します。
- **補助ソース：** Web検索。売出状況・価格変更・エリア相場の動きを補足します。
  ポータルへの直接アクセスは遮断されているため、検索要約で裏が取れない項目は
  「未確認」と明記します。

#### スプレッドシートの列

`区分 / 物件名 / 号室 / 所在 / 駅徒歩 / 築年月 / 階 / 専有面積(㎡) / 間取り / 向き /
売出価格(万円) / 成約価格(万円) / 売出日 / 成約日・更新日 / 販売日数 /
管理費+修繕積立金(円/月) / 特徴・備考 / 情報源`

`区分` に入れる値：`自社売出中` / `成約` / `売出履歴` / `競合` / `新規売出`

成約を1行足すだけで翌日の配信に反映されます。既存行は削除せず追記していく運用です。

いずれの場合も、**数値はソースの値をそのまま使い、推測で補完しない**こと。
確認できなかった項目は空欄にせず「未確認」と明記します。

## ルーティンのプロンプト（社内情報は伏せてあります）

```text
【定期実行】コスモ南万騎ヶ原 1st PLACE の日次マーケットレポートの時間です。
この会話で決めた手順どおりに実行してください。

■ 対象物件（自社／提携先案件）
<物件概要：所在・築年・階・面積・間取り・向き・管理費等・売出価格・媒介会社・価格経緯>

■ 手順
1. 基準日を日本時間（JST）で確認する。
2. Google Drive の read_file_content で fileId <SPREADSHEET_ID> を読む。
   区分は 自社売出中 / 成約 / 売出履歴 / 競合 / 新規売出。
   このシートが成約情報・新規売出情報の一次ソース。
   該当データが無くてもエラーにせず「当月の成約入力なし」として扱う。
3. Web検索で売出状況・価格変更・エリア相場を補足する。
   ポータルとREINSへは直接アクセスできないため、検索要約で確認できない項目は
   必ず「未確認」と明記し、推測値で埋めない。
4. 販売開始日からの通算日数と、直近の価格改定からの経過日数を両方計算する。
5. Gmail の send_message で送信する。
   宛先 <RECIPIENTS> ／ 件名「【コスモ南万騎ヶ原 日次レポート】YYYY年M月D日(曜)」／
   htmlBody で「① 自社物件の現況／② 今月の成約／③ 新規売出／
   ④ ライバル物件／⑤ 所見」の順に表を使って構成する。
6. 数値はシートと検索結果の値をそのまま使い、推測で補完しない。
7. 送信後、件名・宛先・掲載した成約件数／新規売出件数を報告して終了する。

■ 注意
この情報は社外秘。指定の宛先以外に送信したり、外部サービスへ投稿したりしないこと。
スプレッドシートの既存データは削除・上書きしないこと（読み取りのみ）。
```

### 起動モード

既存セッションを継続する方式（self-bind）で登録しています。
Gmail・Google Drive のコネクタは実行セッション側が保持しているため、
新規セッションを毎回起こす方式にすると、これらのツールが使えず配信できません。

## 運用メモ

- 販売日数は「販売開始日からの通算日数」と「直近の価格変更からの経過日数」を
  併記します。値下げ判断は後者を重視します。
- 同マンションは過去に「価格設定を誤ると1年以上動かない」事例があるため、
  成約事例は必ず販売日数とセットで記載します。
- 同マンションは過去に「価格設定を誤ると1年以上動かない」事例があるため、
  成約事例は必ず販売日数とセットで記載します。
- 「未確認」と書かれた項目が続く場合は、スプレッドシートへの入力が滞っている
  サインです。成約・新規売出は手動での転記が必要です。
