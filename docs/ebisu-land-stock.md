# 恵比寿 物件在庫の日次蓄積

渋谷区・恵比寿エリアの売り物件を毎日ためて、
**「今日で何件あるか」「今月どの種別が何件はけたか」「その推移」** を出し続けるための仕組みです。

集計する種別は5つ。

| 種別 | 含まれるもの |
| --- | --- |
| 土地 | 売地・宅地・更地 |
| 戸建 | 中古／新築一戸建、テラスハウス |
| アパート | 一棟アパート・一棟マンション・共同住宅（収益一棟） |
| ビル | 一棟ビル、事務所、店舗、倉庫などの事業用 |
| マンション(区分) | 区分所有のマンション1戸 |

## 仕組み

```
毎日の物件情報 ──▶ 取込シート ──▶ 物件マスタ（差分を反映）
                                   ├─▶ 日次サマリ（種別ごとの在庫・新規・掲載終了・値下げ）
                                   ├─▶ 月次サマリ（月初在庫・新規・掲載終了・月末在庫・平均掲載日数）
                                   └─▶ 価格履歴（値上げ・値下げの記録）

国交省API ──────▶ 成約実績シート（実際の取引価格。掲載終了の答え合わせ用）
```

毎日1回 `runDailyLandStock()` が動けば、あとは勝手にたまっていきます。

### 何をもって「売れた」とするか

在庫データから直接分かるのは**「掲載が消えた」**ことだけです。成約なのか売止め・
取下げなのかは、掲載情報だけでは区別できません。そのためこの仕組みでは：

1. 掲載が消えた件数を **「掲載終了」** として月次で数える（＝成約＋取下げ）
2. そのうち **値下げなしで終了した件数** を別列で持つ（成約の目安になりやすい）
3. 実際の成約は、国交省「不動産情報ライブラリ」の取引価格情報で四半期ごとに答え合わせする
   （`LandStockReinfolib.gs`）

国交省のデータは公表が4〜5か月遅れるので、当月の判断には使えません。
速報値として掲載終了を見て、確定値として成約実績を後から突き合わせる、という運用になります。

### 掲載終了の判定

- ある物件が **3日連続で取込に現れなかったら**「掲載終了」にします（`LS_GRACE_DAYS` で変更可）
- 掲載終了日は **最後に確認できた日** を記録します
- そのため直近数日の掲載終了件数は、後から増えることがあります
  （日次サマリは毎回、直近21日ぶんを作り直して自動的に整合させています）
- **その日の取込が0件だった場合は、掲載終了の判定をしません**。
  収集が失敗した日に在庫が全滅する事故を防ぐためです
- いったん消えた物件が再び現れたら、掲載終了を取り消して「再掲載」と備考に残します

## データの入れ方

物件情報をどこから取ってくるかは、この仕組みの外側の話です。入れ方は3通り用意してあります。

> ポータルサイト（SUUMO・アットホーム等）を自動巡回して集めるのは、各社の利用規約で
> 禁止されているのが通常です。この仕組みは、**レインズの書き出しや自社で集めた情報**を
> 入れる前提で作ってあります。

### A. 取込シートに直接貼る（手作業・少量向き）

`取込` シートの2行目以降に貼るだけ。列は次のとおりで、**空欄があっても構いません**。

| 列 | 内容 |
| --- | --- |
| 取得日 | 空欄なら実行日が自動で入ります |
| 情報元 | レインズ／自社／業者名など |
| 元物件ID | 物件番号。あると同一物件の追跡が正確になります |
| 種別 | 「売地」「中古一戸建」など、表記ゆれのままでOK |
| 所在地 | 「渋谷区恵比寿南1-2-3」など |
| 最寄駅 / 徒歩分 | |
| 価格 | 「1億2,000万円」「9800万円」「12000」どれでも読めます |
| 土地面積 / 建物面積 | 「132.45㎡」「40坪」どちらでも読めます |
| 間取り / 築年月 / 階数 | |
| 掲載URL / 備考 | |

### B. Google ドライブのフォルダにCSVを置く（レインズの書き出し向き）

1. ドライブにフォルダを作り、そのIDを `LS_CSV_FOLDER_ID` に登録
2. 毎日そこにCSVを放り込む
3. `runDailyLandStock()` が読み取って `取込` シートへ追記し、ファイルはフォルダ内の `済` へ移動します（消しません）

CSVのヘッダー名は表記ゆれを吸収します（「物件番号」「販売価格」「専有面積」なども認識）。
文字コードが Shift_JIS のときは `LS_CSV_CHARSET` に `Shift_JIS` を設定してください。

### C. ウェブアプリへPOST（アプリ連携向き）

`Receiver.gs` を同じプロジェクトに入れておくと、`type: 'land'` でPOSTした行が `取込` シートに入ります。

```json
{ "token": "合言葉", "type": "land", "from": "収集アプリ",
  "rows": [{ "種別": "売地", "所在地": "渋谷区恵比寿1-2-3", "価格": "1億2000万円", "土地面積": "100㎡" }] }
```

## シート構成

| シート | 内容 |
| --- | --- |
| `取込` | 毎日の生データ。入れたものはそのまま残ります |
| `物件マスタ` | 物件1件1行。初回確認日・最終確認日・掲載日数・状態・価格の推移 |
| `価格履歴` | 値上げ・値下げの記録 |
| `日次サマリ` | 日付 × 種別の在庫件数・新規・掲載終了・値下げ・中央値 |
| `月次サマリ` | 年月 × 種別の月初在庫・新規・掲載終了・月末在庫・平均掲載日数 |
| `取込ログ` | 実行ごとの件数記録。動いているかの確認用 |
| `成約実績` / `成約実績・四半期` | 国交省APIから取り込んだ実際の取引（任意） |

**エリア外の行は消しません。** `取込` シートには残したまま、集計から外すだけです
（何件外したかは `取込ログ` の「エリア対象外」に出ます）。

## 導入手順

1. Google ドライブでスプレッドシートを新規作成する（例：恵比寿 物件在庫）
2. **拡張機能 → Apps Script** を開き、次のファイルを貼り付ける
   - `gas/LandStock.gs`（必須）
   - `gas/LandStockMailer.gs`（毎朝メールが要るなら）
   - `gas/LandStockReinfolib.gs`（成約実績の裏取りが要るなら）
3. **プロジェクトの設定 → スクリプト プロパティ** に必要なものを登録する（下表）
4. `setupLandStockSheets` を1回実行してシートを作る（初回は権限の確認が出ます）
5. `取込` シートに手元の物件を何件か入れて、`runDailyLandStock` を実行する
6. `物件マスタ` と `日次サマリ` に行ができていればOK
7. **トリガー → トリガーを追加** で毎日の実行を設定する
   - 実行する関数：`runDailyLandStock`（メールも送るなら `sendLandStockMail`）
   - イベントのソース：時間主導型 ／ 日付ベースのタイマー ／ 午前6時〜7時
   - ※ `sendLandStockMail` は先に集計を実行してから送るので、トリガーは1本で足ります

### スクリプトプロパティ

| プロパティ | 既定 | 内容 |
| --- | --- | --- |
| `LS_AREA_KEYWORDS` | `恵比寿` | 対象エリアの判定語。カンマ区切りで増やせます |
| `LS_GRACE_DAYS` | `3` | 何日連続で見つからなければ掲載終了とみなすか |
| `LS_SPREADSHEET_ID` | （不要） | 別ファイルを対象にする場合のみ |
| `LS_CSV_FOLDER_ID` | （任意） | 日次CSVを置くドライブのフォルダID |
| `LS_CSV_CHARSET` | `UTF-8` | CSVの文字コード。レインズ等は `Shift_JIS` |
| `LS_DAILY_REBUILD_DAYS` | `21` | 日次サマリを作り直す日数 |
| `LS_RECIPIENT` | （メール時必須） | まとめメールの送信先 |
| `LS_CC` | （任意） | CCアドレス。カンマ区切り |
| `LS_RUN_BEFORE_MAIL` | `true` | `false` にするとメール前の集計をしない |
| `LS_TREND_MONTHS` | `6` | メールの月次推移に載せる月数 |
| `REINFOLIB_API_KEY` | （API利用時必須） | 不動産情報ライブラリのAPIキー |
| `RL_CITY_CODE` | `13113` | 市区町村コード（渋谷区） |
| `RL_YEARS_BACK` | `3` | 成約実績をさかのぼる年数 |

## 毎朝のまとめメール

`sendLandStockMail()` が次の内容を1通で送ります。送る前に `previewLandStockMail()` で
実行ログに文面を出して確認できます（**確認するまでは送信されません**）。

- いまの在庫：種別ごとの件数と前日比
- 当日の動き：新規・掲載終了・値下げ、中央値価格と中央値坪単価
- 今月の動き：月初在庫・新規・掲載終了・現在・平均掲載日数
- 月次の推移：直近6か月の掲載終了件数と月末在庫

## 成約実績の取り込み（任意）

`fetchEbisuTrades()` で、国交省「不動産情報ライブラリ」の取引価格情報から
渋谷区ぶんを取得し、地区名に恵比寿を含むものだけを `成約実績` シートへためます。
同じ取引は取り込み直しても重複しません。

- APIキーは https://www.reinfolib.mlit.go.jp/ で発行し、`REINFOLIB_API_KEY` に登録
- 公表が四半期ごとなので、トリガーは**月1回**で十分です
- エンドポイント・パラメータ・項目名は公式の仕様書と突き合わせて確認してください
  （仕様が変わっても止まらないよう、取得できない四半期は読み飛ばして先に進みます）
- この統計では、アパートやビルなど一棟物は「宅地(土地と建物)」に含まれるため、
  在庫側の種別と1対1には対応しません。件数の傾向を見るための参考値として扱ってください

## 動かす前の確認

`LandStock.gs` を直したときは、Apps Script に貼る前にロジックだけ確認できます。

```
node test/landstock.test.js
```

価格・面積の読み取り、掲載終了の判定、日次・月次サマリの数え方を検証します。

## 運用上の注意

- **毎日走らせること。** 収集が飛んだ日があると、掲載終了の判定がその分ずれます
- 直近数日の掲載終了件数は後から増えます。締めた数字が必要なら、月が変わってから月次サマリを見てください
- 元物件IDが入っていない場合は、種別・所在地・面積・間取り・築年月から物件キーを作ります。
  価格はキーに含めないので、値下げしても同じ物件として追えます
- 情報元をまたいで同じ物件が二重に載ると、別物件として数えられます。
  重複を減らしたいときは、情報元をどれか1つに絞るのが確実です
