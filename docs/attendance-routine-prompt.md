# Claude ルーティン設定（朝の出社メンバー一覧メール）

平日 8:00（JST）にこのセッションを起こし、当日の出社メンバー一覧をメール送信します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 23 * * 0-4` |
| 対応する日本時間 | 月〜金 8:00 |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |
| 送信方法 | 自動送信 |

cron を UTC で書く点に注意。日本時間 8:00 は UTC 23:00 で日付が前日に戻るため、
曜日指定も1日ずらして `0-4`（日〜木）になります。営業日報まとめメールと同じ時刻です。

## ルーティンのプロンプト

社内情報（スプレッドシートID・カレンダーID・宛先アドレス）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】本日の出社メンバー一覧メールの時間です。この会話で決めた手順どおりに実行してください。

対象日は「実行日（JST）当日」。当社休日は水曜・日曜。勤務表の当日列が全員「休み」なら
「本日は出社予定者がいません」と明記して送る。

1. 勤務表を読む：Google Drive の read_file_content で fileId `<KINMU_SPREADSHEET_ID>`（勤務表・下期）。
   出力が大きいので保存されたファイルを jq/awk で当月シートの当日列だけ抜き出す。
   各メンバーは2行組で、上段が勤務区分・下段が備考欄。列は「氏名＼日」行の日付ヘッダで
   位置を確認してから読むこと（ずれやすい）。
   最終行の「勤務人数」と自分の集計人数が一致するか必ず突き合わせる。一致しなければ送らずに報告して終了。

2. 勤務区分→時間帯：S=10:00〜18:00 / S2=11:00〜19:00 / S3=12:00〜20:00 / A=10:00〜15:00 /
   B=13:00〜18:00 / C=10:30〜15:30 / 横浜A=横浜支店10:00〜15:00 / 横浜B=横浜支店13:00〜18:00 / F=在宅勤務。
   休み・✖（公休）・有休・半休・特休・代休・夏休・冬休・欠勤は出社なし。
   フレックス・時間指定・セルに直接書かれた時刻（例「13時〜16時」「10～13」）は記載をそのまま使う。
   備考欄に時刻があれば備考を優先。読めない記号は推測で埋めず「要確認」に出す。

3. 予定を重ねる：Google Calendar の list_events で calendarId `<CYBOZU_CALENDAR_ID>`（サイボウズ Office）
   の当日分を取得。参加者は description の「■参加者」行から取る。
   件名が「やること:」で始まるもの、および終日・複数日にまたがる「重要:」の通達枠は一覧に出さない。
   時刻付きの「重要:」「外出:」「来客:」「面接:」やその他の予定は出す。終日予定は時刻を書かず名称だけ添える。
   「在宅」を含む予定の本人は出社ではなく在宅に分類する。

4. Gmail の send_message で送信。宛先 <RECIPIENT> ／
   件名「【本日の出社予定】YYYY年M月D日(曜)　出社N名」／
   htmlBody で「小林様　お世話になっております。」＋出社の表（時間・氏名・本日の予定、出社時刻の早い順）＋
   「■ 在宅」＋「■ 休み」＋「■ 要確認」（休みなのに予定の参加者になっている人、勤務時間外の予定など）＋
   末尾に「※ 勤務表とサイボウズ Office の予定から自動作成しています。」と
   「※ サイボウズの取り込み最終更新：M月D日 HH:MM」（list_events が返すカレンダーの updated 値をJSTで記載）。
   数字・時刻はデータの値をそのまま使い、推測で補完しない。

5. 正しく集計できない場合はメールを送らず、原因を報告して終了する。

このデータは社外秘。指定の宛先以外に送信したり、外部サービスへ投稿したりしないこと。
送信後は件名・出社人数・休みの人数を報告して終了。
```

## 運用メモ

- **列ずれに注意。** 勤務表は月ごとに日数が違い、行頭に空列が入る。日付ヘッダ行で必ず位置合わせをする。
  検算として最終行の「勤務人数」と突き合わせている。
- **サイボウズの取り込みは数時間おき。** 当日朝に急遽入った予定は 8:00 のメールに載らないことがあるため、
  取り込み時刻を本文に明記している。
- 祝日も配信される。勤務表側で全員「休み」になっていれば、その旨のメールになる。
- 翌月分の勤務表が未入力の場合は「勤務表が未入力」と明記し、推測で埋めない。
- ルーティンは既存セッションに紐付いている。セッションが終了・アーカイブされるとコネクタを
  失って動かなくなるため、その場合は新しいセッションで登録し直す。
