# Claude ルーティン設定（翌日の出社メンバー一覧メール）

営業日の前日 18:00（JST）にこのセッションを起こし、翌日の出社メンバー一覧をメール送信します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 9 * * 0,1,3,4,5` |
| 対応する日本時間 | 日・月・水・木・金の 18:00 |
| 対象日 | 実行日の翌日（月・火・木・金・土） |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |
| 宛先 | 小林様・森様（常に）＋ 翌日が出社または在宅の全員 |
| 送信方法 | 自動送信 |

18:00 JST は 09:00 UTC で日付がまたがらないため、曜日はそのままで済みます。
当社休日が水曜・日曜なので、その前日にあたる**火曜と土曜の夜は配信しません**
（翌日が休日で「出社0名」になるため）。

## ルーティンのプロンプト

社内情報（スプレッドシートID・カレンダーID・宛先アドレス）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】翌日の出社メンバー一覧メールの時間です。この会話で決めた手順どおりに実行してください。

対象日は「実行日（JST）の翌日」。実行は日・月・水・木・金の18:00 JSTで、翌日は月・火・木・金・土になる。
当社休日は水曜・日曜。万一、翌日の勤務表列が全員「休み」なら「明日は出社予定者がいません」と明記して送る。

1. 勤務表を読む：Google Drive の read_file_content で fileId `<KINMU_SPREADSHEET_ID>`（勤務表・下期）。
   出力が大きいので保存されたファイルを jq/awk で対象月シートの対象日列だけ抜き出す。
   月末の実行では翌日が翌月シートになる点に注意（例：9/30の夜は10月シートの1日列）。
   各メンバーは2行組で、上段が勤務区分・下段が備考欄。列は「氏名＼日」行の日付ヘッダで
   位置を確認してから読むこと（ずれやすい）。
   最終行の「勤務人数」と自分の集計人数（出社＋在宅）が一致するか必ず突き合わせる。
   一致しなければ送らずに報告して終了。

2. 勤務区分→時間帯：S=10:00〜18:00 / S2=11:00〜19:00 / S3=12:00〜20:00 / A=10:00〜15:00 /
   B=13:00〜18:00 / C=10:30〜15:30 / 横浜A=横浜支店10:00〜15:00 / 横浜B=横浜支店13:00〜18:00 / F=在宅勤務。
   休み・✖（公休）・有休・半休・特休・代休・夏休・冬休・欠勤は出社なし。
   フレックス・時間指定・セルに直接書かれた時刻（例「13時〜16時」「10～13」）は記載をそのまま使う。
   備考欄に時刻があれば備考を優先。読めない記号は推測で埋めず「要確認」に出す。

3. 予定を重ねる：Google Calendar の list_events で calendarId `<CYBOZU_CALENDAR_ID>`（サイボウズ Office）
   の対象日分を取得。参加者は description の「■参加者」行から取る。
   件名が「やること:」で始まるもの、および終日・複数日にまたがる「重要:」の通達枠は一覧に出さない。
   時刻付きの「重要:」「外出:」「来客:」「面接:」やその他の予定は出す。終日予定は時刻を書かず名称だけ添える。
   「在宅」を含む予定の本人は出社ではなく在宅に分類する。

4. 宛先を組み立てる。氏名とアドレスの対応表（社員11名分）は実行環境側に持たせる。
   宛先＝小林・森（常に）＋翌日が出社または在宅の全員。休みの人は入れない。重複は除く。
   対応表にない氏名が勤務表に出てきたら、その人は宛先に入れず、
   本文の「■ 要確認」に「◯◯さんのアドレスが未登録です」と明記する。

5. Gmail の send_message で送信。to に4で作った宛先をすべて入れる／
   件名「【明日の出社予定】YYYY年M月D日(曜)　出社N名」／
   htmlBody で「お疲れさまです。明日の出社予定です。」＋
   出社の表（時間・氏名・明日の予定、出社時刻の早い順）＋「■ 在宅」＋「■ 休み」＋
   「■ 要確認」（休みなのに予定の参加者になっている人、勤務時間外の予定、
   午後遅い時間の在席が手薄になる場合、アドレス未登録の人など）＋
   末尾に「※ 勤務表とサイボウズ Office の予定から自動作成しています。」と
   「※ サイボウズの取り込み最終更新：M月D日 HH:MM」（list_events が返すカレンダーの updated 値をJSTで記載）と
   「※ 本日18時時点の予定です。当日朝までに変更が入る場合があります。」。
   宛先が社内メンバー全体に広がるため、本文は社内向けの文面にする（特定個人への敬称呼びかけにしない）。
   数字・時刻はデータの値をそのまま使い、推測で補完しない。

6. 正しく集計できない場合はメールを送らず、原因を報告して終了する。

このデータは社外秘。対応表にあるアドレス以外に送信したり、外部サービスへ投稿したりしないこと。
送信後は件名・出社人数・在宅人数・休みの人数・宛先件数を報告して終了。
```

## 運用メモ

- **列ずれに注意。** 勤務表は月ごとに日数が違い、行頭に空列が入る。日付ヘッダ行で必ず位置合わせをする。
  検算として最終行の「勤務人数」と突き合わせている。
- **月をまたぐ日。** 月末の夜に走るときは翌月シートを読む必要がある。
- **横浜支店勤務（横浜A／横浜B）は本社在席ではない。** 一覧では「横浜支店」と明記する。
- **前夜18時時点の情報である点をメールに明記する。** サイボウズの取り込みは数時間おきで、
  さらに当日朝までに予定が変わることもある。
- 翌日が休日にあたる火曜・土曜の夜は配信しない。祝日は勤務表側で「休み」になっていれば
  「明日は出社予定者がいません」というメールになる。
- 翌月分の勤務表が未入力の場合は「勤務表が未入力」と明記し、推測で埋めない。
- ルーティンは既存セッションに紐付いている。セッションが終了・アーカイブされるとコネクタを
  失って動かなくなるため、その場合は新しいセッションで登録し直す。
- **宛先の対応表はリポジトリに置かない。** 実行環境（ルーティンの設定・会話）側で保持する。
  失われた場合は、過去の社内一斉メールの宛先欄から姓名のローマ字で突き合わせて復元できる。
- **氏名とアドレスの表記ゆれに注意。** 勤務表の姓とアドレスのローマ字が一致しない人がいる
  （読み方の違い・旧姓など）。新しく人が増えたときは、推測でアドレスを当てず必ず確認する。
- 入退社があったら対応表を更新する。未登録の人は宛先に入れず「要確認」に出る仕様。

## 変更履歴

- 当初は「当日朝8:00・小林様のみ」で運用。9/7〜9/9 の3日分を配信。
- 9/9 より「前日18:00・小林様＋森様」に変更。翌日の出社が前夜に分かるようにするため。
  朝8:00の便は停止した。
