# Claude ルーティン設定（翌日の出社予定メール）

毎日 18:00（JST）にこのセッションを起こし、翌日の出社予定を勤務者へ個別送信します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 9 * * *` |
| 対応する日本時間 | 毎日 18:00 |
| 対象日 | 実行日の翌日 |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |
| 宛先 | 下記「宛先の決め方」参照。**1人1通の個別送信** |
| 送信方法 | 自動送信 |

18:00 JST は 09:00 UTC で日付がまたがらないため、曜日はそのままで済みます。

## 宛先の決め方

**曜日で休みを判断しない。** 定休は水曜・日曜だが、祝日・シルバーウィーク・定休日でも
勤務が入っている人がいる。必ず勤務表の実データで判断する。

| 翌日 | 宛先 |
| --- | --- |
| 通常営業日 | 小林・森（常に）＋ 出社または在宅の全員 |
| 定休日・祝日・連休 | **その日に勤務が入っている人だけ**（小林・森も勤務がなければ送らない） |
| 勤務者が0人 | 送信しない |

## 1人1通で送る理由

各メールに「あなたの今月の勤務状況」を入れるため。本人以外に見えてはいけないので、
まとめ送り（複数宛先・cc・bcc）は使わない。名簿部分は全員共通で、個人欄だけが差し替わる。

個人欄に入れるのは3つ。

- 今月ここまでの勤務日数（1日〜対象日の前日）
- 今月の予定勤務日数（行末から3番目の「出勤 日数」列）
- 残り＝予定−ここまで

**在宅の内訳は出さない。** 勤務表は在宅の日も S や C のまま記録されており
（例：9/8の森さんは在宅だが勤務表は S）、勤務表からは在宅を判別できないため。

## ルーティンのプロンプト

社内情報（スプレッドシートID・カレンダーID・氏名とアドレスの対応表）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】翌日の出社予定メールの時間です。この会話で決めた手順どおりに実行してください。

対象日は「実行日（JST）の翌日」。毎日18:00 JSTに走る。
当社の定休は水曜・日曜だが、祝日・シルバーウィーク・定休日でも勤務表に勤務が入っている人がいることがある。
曜日で判断せず、必ず勤務表の実データで判断すること。

1. 勤務表を読む：Google Drive の read_file_content で fileId `<KINMU_SPREADSHEET_ID>`。
   出力が大きいので保存されたファイルを jq/awk で対象月シートを抜き出す。
   月末の実行では翌日が翌月シートになる点に注意（例：9/30の夜は10月シートの1日列）。
   各メンバーは2行組で、上段が勤務区分・下段が備考欄。列は「氏名＼日」行の日付ヘッダで
   位置を確認してから読むこと。
   日付Nの列は awk のフィールドで言うと N+3 番目、氏名は3番目。行末から3番目が「出勤 日数」列。
   最終行の「勤務人数」と自分の集計人数（出社＋在宅）が一致するか必ず突き合わせる。
   一致しなければ送らずに報告して終了。

2. 勤務区分→時間帯：S=10:00〜18:00 / S2=11:00〜19:00 / S3=12:00〜20:00 / A=10:00〜15:00 /
   B=13:00〜18:00 / C=10:30〜15:30 / 横浜A=横浜支店10:00〜15:00 / 横浜B=横浜支店13:00〜18:00 / F=在宅勤務。
   休み・✖（公休）・有休・半休・特休・代休・夏休・冬休・欠勤・空欄は勤務なし。
   フレックス・時間指定・セルに直接書かれた時刻（例「13時〜16時」「10～13」）は記載をそのまま使う。
   備考欄に時刻があれば備考を優先。読めない記号は推測で埋めず「要確認」に出す。

3. 各人の今月カウントを出す。同じ月シートで、その人の行の1日から「対象日の前日まで」を数える。
   ・今月ここまでの勤務日数（勤務区分が入っている日の数。休み系と空欄は数えない）
   ・今月の予定勤務日数（行末から3番目の「出勤 日数」列の値）
   ・残り＝予定−ここまで
   在宅の内訳は出さないこと。勤務表は在宅の日も S や C のまま記録されており、
   勤務表からは在宅を判別できない。
   対象日が月初1日で数える対象がない場合は「今月はこれが初日」と書く。

4. 予定を重ねる：Google Calendar の list_events で calendarId `<CYBOZU_CALENDAR_ID>` の対象日分を取得。
   参加者は description の「■参加者」行から取る。
   件名が「やること:」で始まるもの、および終日・複数日にまたがる「重要:」の通達枠は一覧に出さない。
   時刻付きの「重要:」「外出:」「来客:」「面接:」やその他の予定は出す。終日予定は時刻を書かず名称だけ添える。
   「在宅」を含む予定の本人は、勤務表が S などでも出社ではなく在宅に分類する。

5. 送る相手を決める。氏名とアドレスの対応表（11名）は実行環境側に持たせる。
   ・翌日が通常営業日 → 小林・森（常に）＋翌日が出社または在宅の全員
   ・翌日が定休日・祝日・連休 → その日に勤務が入っている人だけ。小林・森も勤務がなければ送らない。
   ・翌日に勤務者が1人もいない → 誰にも送らず、「全員休みのため送信なし」と報告して終了。
   対応表にない氏名が勤務表に出てきたら、その人には送らず、小林・森宛の本文の「■ 要確認」に
   「◯◯さんのアドレスが未登録です」と明記する。

6. Gmail の send_message で、宛先1人につき1通ずつ個別に送る（to は必ず1件だけ。cc・bccは使わない）。
   今月カウントは本人にしか見えてはいけないので、まとめ送りは絶対にしないこと。
   件名「【明日の出社予定】YYYY年M月D日(曜)　出社N名」／
   htmlBody は次の構成：
   ・「◯◯さん　お疲れさまです。明日の出社予定です。」（宛先本人の氏名）
   ・「■ あなたの今月の勤務状況」…今月ここまで X日勤務／今月の予定 Y日／残り (Y−X)日。
     翌日が本人の勤務日かどうかも1行で書く。この欄は本人宛のみである旨を添える。
   ・「■ 出社（N名）」…時間・氏名・明日の予定の表。出社時刻の早い順。
   ・「■ 在宅」「■ 休み」
   ・「■ 要確認」…休みなのに予定の参加者になっている人、勤務時間外の予定、
     午後遅い時間の在席が手薄になる場合など。他人の勤務日数はここに書かない。
   ・末尾に「※ 勤務表とサイボウズ Office の予定から自動作成しています。」
     「※ サイボウズの取り込み最終更新：M月D日 HH:MM」（list_events が返すカレンダーの updated 値をJSTで記載）
     「※ 本日18時時点の予定です。当日朝までに変更が入る場合があります。」
     「※ 今月の勤務状況はあなた宛のみに記載しています。」
   数字・時刻はデータの値をそのまま使い、推測で補完しない。

7. 正しく集計できない場合はメールを送らず、原因を報告して終了する。

このデータは社外秘。対応表にあるアドレス以外に送信したり、外部サービスへ投稿したりしないこと。
送信後は件名・出社人数・在宅人数・休みの人数・送信通数を報告して終了。
```

## 運用メモ

- **列ずれに注意。** 勤務表は月ごとに日数が違い、行頭に空列が入る。日付ヘッダ行で必ず位置合わせをする。
  検算として最終行の「勤務人数」と突き合わせている。
- **月をまたぐ日。** 月末の夜に走るときは翌月シートを読む必要がある。
- **横浜支店勤務（横浜A／横浜B）は本社在席ではない。** 一覧では「横浜支店」と明記する。
- **前夜18時時点の情報である点をメールに明記する。** サイボウズの取り込みは数時間おきで、
  さらに当日朝までに予定が変わることもある。
- **宛先の対応表はリポジトリに置かない。** 実行環境（ルーティンの設定・会話）側で保持する。
  失われた場合は、過去の社内一斉メールの宛先欄から姓名のローマ字で突き合わせて復元できる。
- **氏名とアドレスの表記ゆれに注意。** 勤務表の姓とアドレスのローマ字が一致しない人がいる
  （読み方の違い・旧姓など）。新しく人が増えたときは、推測でアドレスを当てず必ず確認する。
- 入退社があったら対応表を更新する。未登録の人は宛先に入れず「要確認」に出る仕様。
- ルーティンは既存セッションに紐付いている。セッションが終了・アーカイブされるとコネクタを
  失って動かなくなるため、その場合は新しいセッションで登録し直す。

## 変更履歴

- 当初は「当日朝8:00・小林のみ・1通」で運用。9/7〜9/9 の3日分を配信。
- 9/9 に「前日18:00・小林＋森」へ変更。翌日の出社が前夜に分かるようにするため。朝8:00の便は停止。
- 同日、宛先を「翌日が出社または在宅の全員」に拡大。
- 同日、**毎日18:00・1人1通の個別送信**に変更。定休日や連休でも勤務者がいれば送るようにし、
  各メールに本人だけの今月の勤務日数カウントを追加した。
