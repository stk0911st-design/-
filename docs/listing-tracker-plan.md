# 売り出し物件トラッカー（世田谷・杉並・大田・渋谷）計画メモ

「土地の売り出し」「戸建ての売り出し」を4区（世田谷区・杉並区・大田区・渋谷区）で
カウントし、毎日調べて18:00に小林様へメール報告、月次で蓄積する仕組みの設計メモ。

## このセッションでの制約：Claudeルーティンではデータ取得ができない

このタスクを実行したセッションの環境では、外部サイト（SUUMOなど不動産ポータル）への
アウトバウンド通信が組織のネットワークポリシーでブロックされていた
（`EGRESS_BLOCKED` / プロキシの403系）。これは個別サイトの問題ではなく、
このセッションの環境設定によるもので、セッション側から回避することはできない。

そのため、既存の「営業日報まとめメール」と同じく **Google Apps Script（GAS）方式**
を採用した。GASの `UrlFetchApp` はGoogleのサーバーから直接SUUMOへアクセスするため、
このセッションのネットワーク制限を受けない。

実装：`gas/ListingTracker.gs`（セットアップ手順は `gas/ListingTracker-README.md`）

## データソースと集計方針

- データソース：SUUMO（`https://suumo.jp/`）の一覧ページ
  - 土地：`https://suumo.jp/tochi/tokyo/sc_<区>/`
  - 新築一戸建て：`https://suumo.jp/ikkodate/tokyo/sc_<区>/`
  - 中古一戸建て：`https://suumo.jp/chukoikkodate/tokyo/sc_<区>/`
  - 区コード：setagaya / suginami / ota / shibuya（setagaya・suginamiは検索で実在を確認済み。
    ota・shibuyaは同じ命名規則からの推測で、導入時に `selfTestOneCategory` での確認が必要）
- 「戸建て」は新築・中古の両方を合算して報告する（メールでは種別ごとの内訳も出す）
- 新規件数／消失件数は、前日の物件ID一覧と本日の物件ID一覧を突き合わせて算出する
  （総件数の増減だけでは新規と消失を同時に数えられないため）
- 平均坪単価は、価格・面積の両方が一覧ページから取得できた物件の坪単価の単純平均

## 「成約件数」についての重要な限界

SUUMOなど掲載サイトの情報だけでは、**「成約（売れた）」と「掲載終了」を区別できない**。
掲載が消えた原因には、成約以外に「広告掲載期間の終了」「他社サイトへの一本化」
「価格変更に伴う再掲載（新しい物件IDに変わる）」などがあり得る。

本トラッカーが出す「消失件数」は、あくまで「前日まであった掲載が本日見当たらなく
なった件数」であり、確定した成約件数ではない。この点は毎日のメール本文にも明記する。

正確な成約件数（本当に売れた件数）が必要な場合は、レインズ（指定流通機構）など
成約情報を持つデータソースへの接続が別途必要になる。レインズは会員事業者向けの
システムであり、外部からのスクレイピング等はできない。小林様の会社がレインズの
会員であれば、担当者による手動確認・入力（既存の「日報カウンター」と同じ方式）
を組み合わせる案もある。
