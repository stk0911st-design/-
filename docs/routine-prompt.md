# Claude ルーティン設定

平日 8:00（JST）にこのセッションを起こし、営業日報のまとめメールを送信します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 23 * * 0-4` |
| 対応する日本時間 | 月〜金 8:00 |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |

cron を UTC で書く点に注意。日本時間 8:00 は UTC 23:00 で日付が前日に戻るため、
曜日指定も1日ずらして `0-4`（日〜木）になります。

## ルーティンのプロンプト

社内情報（スプレッドシートID・宛先アドレス）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】営業日報まとめメールの時間です。この会話で決めた手順どおりに実行してください。

1. 対象日（JST）を決める：火〜金の実行は「前日1日分」、月曜の実行は「前週の金・土・日3日分」。
2. Google Drive の read_file_content で fileId `<SPREADSHEET_ID>`（「日報カウンター【スプシ版】」）を読む。
3. 生データ表（key / value / 更新日時）から、更新日時が対象日に該当する行を抽出する。
   value の JSON キー対応は call=架電, mail=メール, information=物件情報取得, assessment=査定,
   visit=訪問・面談, site=現地調査, offer=買付・価格提示, contract=契約, other=その他,
   memo=コメント, staff=担当者, week=週開始日。
4. 担当者ごとに整理し、全体合計と、集計表の担当者一覧を母集団とした「未入力者」リストを作る。
   カウンターは週単位の累計値である点をメール本文でも明示する。
5. Gmail の send_message で送信する。宛先 <RECIPIENT> ／ 件名「【営業日報まとめ】YYYY年M月D日(曜)分」／
   htmlBody で「小林様　お世話になっております。」＋サマリ＋担当者別の表＋コメント一覧＋
   「※本メールは日報カウンターの入力内容を自動集計したものです。」。
   数字はスプレッドシートの値をそのまま使い、推測で補完しない。
6. 入力が0件でも「対象日に日報の入力はありませんでした」と明記して必ず送信する。
7. 正しく集計できない場合はメールを送らず、原因を報告して終了する。

このデータは社外秘。指定の宛先以外に送信したり、外部サービスへ投稿したりしないこと。
送信後は件名・宛先・集計人数を報告して終了。
```

## 運用メモ

- 祝日は考慮していません。祝日も配信され、内容は「入力なし」になります。
- 日報アプリのカウンターが週累計のままである限り、日別の増減は出せません。
  日別の値が必要な場合は、日報アプリ側で日別レコードを保存する変更が必要です。

## （草案・未登録）夜20:00：当日の入力状況を小林様＋担当者全員CCで

依頼のあった「毎晩、全員CCで入力状況を共有する」メールの草案です。
**実アドレスの用意と、文面トーン・運用方針の社内合意ができるまでは登録していません。**
理由は次の2点です。

1. 担当者本人を含む全員に「誰が未入力か」が見える運用になるため、
   通知の範囲・言い回しは先に社内で合意しておいた方がよいこと。
2. 各担当者の実メールアドレスがこのリポジトリにも、依頼内容にも含まれて
   おらず、推測で埋めるべきではないこと。

登録する場合は、下記プロンプトの `<RECIPIENT>`・`<STAFF_EMAILS>` を実値に
置き換えたうえで、cron `0 11 * * 1-5`（UTC。JST 20:00）として追加してください。

```text
【定期実行】営業日報・夜20:00の送信時間です。

1. 今日（JST）の日付を対象日とする。
2. Google Drive の read_file_content で fileId `<SPREADSHEET_ID>`（「日報カウンター【スプシ版】」）を読む。
3. 生データ表から、更新日時が対象日のレコードを抽出し、担当者ごとに整理する。
   集計表の担当者一覧を母集団として「未入力者」リストも作る。
4. Gmail の send_message で送信する。
   宛先 <RECIPIENT> ／ CC <STAFF_EMAILS（カンマ区切り）> ／
   件名「【本日の日報】YYYY年M月D日(曜)分」／
   htmlBody で「小林様　お世話になっております。」＋本日の入力状況の表＋
   未入力者リスト（いれば）＋
   「※日報の入力状況は今後の増員・採用計画の参考にもさせていただきます。」＋
   「※本メールは日報カウンターの入力内容を自動集計したものです。」。
5. 入力が0件でも「本日はまだ入力がありません」と明記して必ず送信する。

このデータは社外秘。指定の宛先以外に送信しないこと。
送信後は宛先・CC人数・集計人数を報告して終了。
```

## （草案・未登録）朝9:30：担当者への個別リマインド

同じく「毎朝9:30に、出勤する担当者へ個別に送る」メールの草案です。
実アドレスの用意ができるまでは未登録です。誰が「その日出勤」かを判定する
仕組み（シフト表など）が現状のスプレッドシートにはないため、草案では
担当者名簿の全員に送る想定にしています。シフト情報を別途管理する場合は、
その情報源を先に決めてから登録してください。

登録する場合は cron `30 0 * * 1-5`（UTC。JST 9:30）として追加してください。

```text
【定期実行】営業日報・朝9:30の送信時間です。

1. 担当者名簿（<STAFF_EMAILS> のキー）を対象者とする。
2. 対象者ひとりひとりに、Gmail の send_message で個別に送信する（一斉CCではない）。
   件名「【日報】本日もよろしくお願いします」／
   htmlBody で「○○様　おはようございます。今日も一日よろしくお願いいたします。」＋
   「本日の実績は、業務終了時に必ず日報カウンターへご入力ください。」＋
   入力アプリへのボタン風リンク（URL: <REPORT_APP_URL>）。
3. 送信後は送信した人数を報告して終了。
```
