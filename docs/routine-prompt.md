# Claude ルーティン設定

平日 8:00（JST）にこのセッションを起こし、営業日報のまとめメールを送信します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 23 * * 0-4` |
| 対応する日本時間 | 月〜金 8:00 |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |

cron を UTC で書く点に注意。日本時間 8:00 は UTC 23:00 で日付が前日に戻るため、
曜日指定も1日ずらして `0-4`（日〜木）になります。

## ルーティンのプロンプト

社内情報（スプレッドシートID・宛先アドレス）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】営業日報まとめメールの時間です。この会話で決めた手順どおりに実行してください。

1. 対象日（JST）を決める：火〜金の実行は「前日1日分」、月曜の実行は「前週の金・土・日3日分」。
2. Google Drive の read_file_content で fileId `<SPREADSHEET_ID>`（「日報カウンター【スプシ版】」）を読む。
3. 生データ表（key / value / 更新日時）から、更新日時が対象日に該当する行を抽出する。
   value の JSON キー対応は call=架電, mail=メール, information=物件情報取得, assessment=査定,
   visit=訪問・面談, site=現地調査, offer=買付・価格提示, contract=契約, other=その他,
   memo=コメント, staff=担当者, week=週開始日。
4. 担当者ごとに整理し、全体合計と、集計表の担当者一覧を母集団とした「未入力者」リストを作る。
   カウンターは週単位の累計値である点をメール本文でも明示する。
5. Gmail の send_message で送信する。宛先 <RECIPIENT> ／ 件名「【営業日報まとめ】YYYY年M月D日(曜)分」／
   htmlBody で「小林様　お世話になっております。」＋サマリ＋担当者別の表＋コメント一覧＋
   「※本メールは日報カウンターの入力内容を自動集計したものです。」。
   数字はスプレッドシートの値をそのまま使い、推測で補完しない。
6. 入力が0件でも「対象日に日報の入力はありませんでした」と明記して必ず送信する。
7. 正しく集計できない場合はメールを送らず、原因を報告して終了する。

このデータは社外秘。指定の宛先以外に送信したり、外部サービスへ投稿したりしないこと。
送信後は件名・宛先・集計人数を報告して終了。
```

## 運用メモ

- 祝日は考慮していません。祝日も配信され、内容は「入力なし」になります。
- 日報アプリのカウンターが週累計のままである限り、日別の増減は出せません。
  日別の値が必要な場合は、日報アプリ側で日別レコードを保存する変更が必要です。

## 追加予定：9:30リマインド／20:00まとめ（未稼働）

平日8:00の従来ルーティンに加えて、次の2つを追加する依頼が来ています。

1. 毎朝9:30：その日出勤する担当者へ個別に「本日分を入力してください」を送る（入力ボタン付き）。
2. 毎晩20:00：当日分のまとめを小林様へ送り、未入力者がいれば全担当者もCCに加える。
   本文には「未入力の場合は稼働記録なしとして扱う」旨の注意と、
   「今後の採用状況にも関わる」ことを柔らかく伝える一文を入れる。

この2つは `gas/DailyReportMailer.gs` の `sendMorningReminderMail` / `sendEveningReportMail` として
実装済みだが、Claude ルーティン版としてはまだ有効化していない。理由：

- 担当者の実際のメールアドレス一覧（`STAFF_EMAILS` 相当）がこのリポジトリにない。
- 「未入力者の情報を担当者全員に共有する」「入力有無を採用評価に結びつける」は、
  社内の人事運用に関わる判断であり、実際に配信を始める前に社内で内容を確認したほうがよい。

上記が確認でき、担当者一覧・宛先が用意できたら、8:00の設定にならって
cron（9:30 JST → UTC 0:30、20:00 JST → UTC 11:00、曜日は運用方針に合わせて設定）と
プロンプトをこの節に追記して有効化する。
