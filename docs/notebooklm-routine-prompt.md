# Claude ルーティン設定（NotebookLM 用ログの更新）

平日の夜に当月分の `営業日報ログ_YYYY-MM` を作り直し、NotebookLM のソースを最新にします。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `30 11 * * 1-5` |
| 対応する日本時間 | 月〜金 20:30 |
| 起動モード | 既存セッションを継続（Google ドライブのコネクタを保持しているため） |

日本時間 20:30 は UTC 11:30 で同じ日付のため、曜日はそのまま `1-5`（月〜金）です。
（朝8時のまとめメールと違い、日付をまたがない点に注意）

## ルーティンのプロンプト

社内情報（スプレッドシートID・フォルダID）は伏せています。
実際のルーティンには実値を入れて登録してください。

```text
【定期実行】NotebookLM 用 営業日報ログの更新です。この会話で決めた手順どおりに実行してください。

1. Google Drive の read_file_content で fileId `<SPREADSHEET_ID>`（「日報カウンター【スプシ版】」）を読む。
2. 生データ表（key / value / 更新日時）から、当月（JST）に入力された行をすべて抽出する。
   **日付は「更新日時」列ではなく、value の JSON 内の `updated`（UTC の ISO 形式）を JST に
   変換して判定する。**「更新日時」列はスプレッドシートのタイムゾーン設定（現状は米国時間）で
   表示されており、JST とは約16時間ずれるため使わないこと。
   value の JSON キー対応は call=架電, mail=メール, information=物件情報取得, assessment=査定,
   visit=訪問・面談, site=現地調査, offer=買付・価格提示, contract=契約, other=その他,
   memo=コメント, staff=担当者, week=週開始日。
3. 当月分の内容を次の構成でまとめる（体裁は docs/templates/notebooklm-monthly-log-template.md）。
   - 冒頭に「この数字は週単位の累計値」「入力があった時点のスナップショット」の注意書き
   - 日別セクション（日付・曜日／担当者ごとの各項目と合計／コメント／その日の未入力者）
   - 週次サマリ（週開始日ごとに、その週の最終入力値を担当者別に）
   - 月次サマリ（担当者別の最新週累計、項目別の傾向、コメントの要約）
   数字はスプレッドシートの値をそのまま使い、推測で補完しない。入力が無い日は「入力なし」と書く。
4. Google Drive の create_file で、parentId `<FOLDER_ID>`（NotebookLM_営業日報）に
   タイトル `営業日報ログ YYYY-MM`（当月）で新しいドキュメントを作成する。
5. 作成が成功したことを確認してから、同じフォルダにある同名の古いドキュメントを
   trash_file でゴミ箱へ移す。順序を逆にしないこと（先に消さない）。
   同名ファイルが見つからない場合は何も消さずに次へ進む。
6. 月が替わった直後（当月分の入力がまだ無い日）は、前月分のドキュメントには手を触れず、
   当月分だけを作成する。前月分は確定済みとして以後更新しない。
7. 実行後は「作成したドキュメント名・対象期間・反映した入力件数・ゴミ箱へ移した旧版の有無」を報告して終了する。

このデータは社外秘。NotebookLM_営業日報 フォルダ以外へは書き出さず、メール送信や外部サービスへの
投稿は行わないこと。フォルダ内の 00_営業日報 データ定義 と、自分が今回作成した以外のファイルは
削除・変更しないこと。
```

## 運用メモ

- 新しいセッションを毎回立ち上げる方式にすると、ルーティンから Google ドライブのコネクタを
  引き継げず失敗します（この環境ではルーティン作成時にコネクタを指定できないため）。
  そのため「既存セッションを継続」で登録しています。
  もし実行時に「ドライブが使えない」と報告された場合は、claude.ai のルーティン画面から
  Google ドライブを指定して登録し直してください。

- NotebookLM 側の反映はドライブ更新から数分後です。夜の実行なら翌朝には最新になっています。
- 実行が失敗した日があっても、翌営業日の実行で当月分をまるごと作り直すため取りこぼしません。
- **「更新日時」列は JST ではありません。** スプレッドシートのタイムゾーンが米国時間のままのため、
  JST とは約16時間ずれます（例：JST 8/26 10:47 の入力が「2026/08/25 18:48」と表示される）。
  日付の判定には value の JSON の `updated`（UTC）を使ってください。
  スプレッドシートの ファイル → 設定 → タイムゾーン を「東京」に変えれば列も JST になりますが、
  過去の表示もまとめて変わるため、変更する場合は朝のまとめメール側の挙動も合わせて確認してください。
- 担当者が増減したときは `00_営業日報 データ定義` の担当者一覧も更新してください
  （NotebookLM の「未入力者」の答えがこの一覧を基準にするため）。
