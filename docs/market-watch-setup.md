# 都心3区マンション ウォッチの導入手順

千代田区・中央区・港区の高級マンションについて、
**成約（実際に売れたもの）** と **売出中（いま出ているもの）** を1つのスプレッドシートに
ためていく仕組みです。坪単価は自動計算されます。

所要 30分ほど。日報の受け皿と同じく、すべてご自身の Google アカウントで完結します。

---

## 全体像

| データ | 出どころ | 入り方 |
| --- | --- | --- |
| 成約・取引価格 | 国土交通省「不動産情報ライブラリ」API | **自動**（週1回の取り込み） |
| 売出中の物件 | レインズ／自社／ポータルから手入力 | **手入力**（`売出ウォッチ` シート） |
| 坪単価・経過日数・値下げ率 | 上記から計算 | **自動** |
| 週次ダイジェストメール | 上記の集計 | **自動**（任意） |

> **なぜ売出中は手入力なのか**
> 売出中の物件情報は、各ポータルサイトの掲載データです。機械で一括取得することは
> 各社の利用規約で認められていません。レインズをお使いになれるお立場なので、
> 検索結果からの貼り付けがいちばん確実で早いです。

---

## ステップ1：APIキーを申請する（審査に5営業日）

**先にこれを出しておいてください。** 審査待ちの間に残りの準備ができます。

1. [不動産情報ライブラリ API利用申請](https://www.reinfolib.mlit.go.jp/api/request/) を開く
2. 利用規約に同意して必要事項を入力
3. 審査後、メールでAPIキーが届く（目安5営業日）

無料です。国交省が公開している取引価格情報・成約価格情報が取れます。

---

## ステップ2：スプレッドシートとスクリプトを用意する

1. Google ドライブで新しいスプレッドシートを作る（例：`都心3区マンションウォッチ`）
2. **拡張機能 → Apps Script**
3. 最初の `function myFunction() {}` を全部消して、`gas/MarketWatch.gs` の中身を貼り付ける
4. 保存（Ctrl+S）

## ステップ3：APIキーを設定する

1. 左の歯車 **プロジェクトの設定**
2. **スクリプト プロパティ → プロパティを追加**

   | プロパティ | 値 | 必須 |
   | --- | --- | --- |
   | `REINFOLIB_KEY` | 届いたAPIキー | ○ |
   | `RECIPIENT` | ダイジェストメールの宛先 | メールを使うなら |
   | `CC` | CCアドレス（カンマ区切り） | 任意 |
   | `MIN_PRICE` | 高級帯とみなす下限価格（円）。既定 `100000000`（1億円） | 任意 |

3. 保存

## ステップ4：シートを作って、動かしてみる

1. 関数の選択欄で **`setupMarketWatch`** を選び、実行
   - 初回は権限の確認が出ます。「詳細 → （プロジェクト名）に移動 → 許可」
   - `成約データ` `売出ウォッチ` `月次サマリ` `_watchlog` の4タブができればOK
2. 次に **`importLatestTransactions`** を実行
   - 直近8四半期ぶんを3区まとめて取り込みます。数分かかります
   - `成約データ` に行が入り、`月次サマリ` に区ごとの平均・中央値が出ます
3. **`previewMarketDigest`** を実行して、実行ログでメール文面を確認（送信されません）

## ステップ5：自動化する

**トリガー → トリガーを追加** で2つ登録します。

| 実行する関数 | ソース | タイミング | 役割 |
| --- | --- | --- | --- |
| `importLatestTransactions` | 時間主導型・週タイマー | 毎週月曜 午前6時〜7時 | データ取り込みと再集計 |
| `sendMarketDigest` | 時間主導型・週タイマー | 毎週月曜 午前8時〜9時 | ダイジェストメール送信 |

メールが不要なら、下のトリガーは登録しなくて構いません。

## 売出ウォッチ表の使い方

`売出ウォッチ` タブに、追いたい物件を1行1件で入れていきます。
**色の付いていない列だけ**埋めてください。残りは自動で計算されます。

| 列 | 入力 | 内容 |
| --- | --- | --- |
| 登録日 | 手 | 表に載せた日 |
| 状態 | 手 | `売出中` / `商談中` / `成約` / `取下` |
| 区 | 手 | 千代田区・中央区・港区 |
| 所在 | 手 | 町丁目まで（例：港区南麻布4） |
| 物件名・部屋番号 | 手 | |
| 売出価格(万円) | 手 | 現在の売出価格 |
| 当初価格(万円) | 手 | 最初に出たときの価格。値下げ率の計算に使います |
| 専有面積(㎡) | 手 | |
| **坪単価(万円)** | **自動** | 売出価格 ÷（面積 ÷ 3.305785） |
| 間取り・階・築年 | 手 | |
| 売出日 | 手 | 日付で入れてください（経過日数の計算に使います） |
| **経過日数** | **自動** | 売出日から今日まで |
| **値下げ率(%)** | **自動** | （当初価格 − 売出価格）÷ 当初価格 |
| 成約価格(万円)・成約日 | 手 | 決まったら入れる。状態も `成約` に |
| 情報元・メモ | 手 | レインズ／自社／ポータル名など |

自動列は `refreshWatchlist` を実行するか、週次の取り込みトリガーが回ったときに更新されます。

### 売れ行きを見るときのポイント

ダイジェストメールでは次の2つを毎週出しています。

- **90日以上 売れ残り** の件数 … 高級帯は動きが遅いので、90日が一つの目安
- **値下げがあった** 物件 … 在庫が膨らんだときに最初にここへ出ます

成約価格まで入れ続けると、`売出価格 → 成約価格` の乖離率が
自社の査定精度そのものになります。半年ためると効いてきます。

## 注意点

- **成約データは遅れます。** 不動産情報ライブラリの公表は四半期ごとで、
  直近の取引が載るまで数カ月かかります。「いま売れたもの」をリアルタイムに知る用途には
  向きません。そこはレインズと `売出ウォッチ` 表で補ってください。
- **APIは連続実行しない。** 国交省から間隔を空けるよう案内が出ています。
  スクリプト側で1.2秒待つようにしてありますが、手で連打しないでください。
- **重複は入りません。** 同じ四半期を2回取り込んでも、既にある行は飛ばします。
  過去分をまとめて入れたいときは `importTransactionsRange(2020, 1, 2026, 1)` のように
  引数付きで実行してください（Apps Script のエディタから引数を渡す場合は、
  一時的に呼び出し用の関数を作るのが簡単です）。
- **社内情報は書かない。** 宛先アドレス・スプレッドシートIDはスクリプトプロパティ側で
  管理し、このリポジトリには置かない方針です。
