# 都心3区マンション ウォッチの導入手順

千代田区・中央区・港区の高級マンションについて、
**売れたもの**と**いま売り出ているもの**を1つのスプレッドシートにためていく仕組みです。
坪単価・経過日数・値下げ率・成約との乖離率は、すべて自動で計算されます。

所要 30分ほど。日報の受け皿と同じく、すべてご自身の Google アカウントで完結します。

---

## 全体像

| データ | 出どころ | 入り方 |
| --- | --- | --- |
| 成約・取引価格 | 国土交通省「不動産情報ライブラリ」API | **自動**（週1回の取り込み） |
| 売出中の物件 | 公開ポータル・自社情報から貼り付け | **手入力**（`売出ウォッチ` シート） |
| 坪単価・経過日数・値下げ率・乖離率 | 上記から計算 | **自動** |
| 価格改定の履歴 | 売出価格を書き換えた瞬間に記録 | **自動** |
| 週次ダイジェストメール | 上記の集計 | **自動**（任意） |

### 売出中の物件を自動取得しない理由

各ポータルサイトの掲載データを機械でまとめて取得することは、各社の利用規約で
認められていません。ここは手入力にしています。

そのかわり、**入力する項目を最小限にしてあります**。1件あたり実質7項目です。
残りは入力した瞬間に自動で埋まります（後述）。

---

## ステップ1：APIキーを申請する（審査に5営業日）

**先にこれを出しておいてください。** 審査待ちの間に残りの準備ができます。

1. [不動産情報ライブラリ API利用申請](https://www.reinfolib.mlit.go.jp/api/request/) を開く
2. 利用規約に同意して必要事項を入力
3. 審査後、メールでAPIキーが届く（目安5営業日）

無料です。国交省が公開している取引価格情報・成約価格情報が取れます。

---

## ステップ2：スプレッドシートとスクリプトを用意する

1. Google ドライブで新しいスプレッドシートを作る（例：`都心3区マンションウォッチ`）
2. **拡張機能 → Apps Script**
3. 最初の `function myFunction() {}` を全部消して、`gas/MarketWatch.gs` の中身を貼り付ける
4. 保存（Ctrl+S）

## ステップ3：APIキーを設定する

1. 左の歯車 **プロジェクトの設定**
2. **スクリプト プロパティ → プロパティを追加**

   | プロパティ | 値 | 必須 |
   | --- | --- | --- |
   | `REINFOLIB_KEY` | 届いたAPIキー | ○ |
   | `RECIPIENT` | ダイジェストメールの宛先 | メールを使うなら |
   | `CC` | CCアドレス（カンマ区切り） | 任意 |
   | `MIN_PRICE` | 高級帯とみなす下限価格（円）。既定 `100000000`（1億円） | 任意 |

3. 保存

## ステップ4：シートを作って、動かしてみる

1. 関数の選択欄で **`setupMarketWatch`** を選び、実行
   - 初回は権限の確認が出ます。「詳細 → （プロジェクト名）に移動 → 許可」
   - `成約データ` `売出ウォッチ` `価格履歴` `月次サマリ` `_watchlog` の5タブができればOK
2. 次に **`importLatestTransactions`** を実行
   - 直近8四半期ぶんを3区まとめて取り込みます。数分かかります
   - `成約データ` に行が入り、`月次サマリ` に区ごとの平均・中央値が出ます
3. **`previewMarketDigest`** を実行して、実行ログでメール文面を確認（送信されません）

## ステップ5：自動化する

**トリガー → トリガーを追加** で3つ登録します。

| 実行する関数 | ソース | タイミング | 役割 |
| --- | --- | --- | --- |
| `importLatestTransactions` | 時間主導型・週タイマー | 毎週月曜 午前6時〜7時 | データ取り込みと再集計 |
| `sendMarketDigest` | 時間主導型・週タイマー | 毎週月曜 午前8時〜9時 | ダイジェストメール送信 |
| `onEditMarketWatch` | **スプレッドシートから・編集時** | — | 入力の自動補完と価格履歴の記録 |

> **3つめは必ず登録してください。** 手入力の負担を減らしている部分がここです。
> トリガーとして登録しないと、価格履歴が残らず、自動補完も効きません。
> （価格履歴シートへの書き込みがあるため、単純トリガーでは権限が足りません）

メールが不要なら、2つめは登録しなくて構いません。

## 売出ウォッチ表の使い方

`売出ウォッチ` タブに、追いたい物件を1行1件で入れていきます。

### 入力するのはこれだけ

| 列 | 例 |
| --- | --- |
| 区 | 港区 |
| 所在 | 港区南麻布4 |
| 物件名 | ○○レジデンス |
| 売出価格(万円) | 33500 |
| 専有面積(㎡) | 88.67 |
| 間取り／階／築年 | 2LDK+S ／ 24階 ／ 2023年 |
| 情報元 | ポータル名・自社 など |

**物件名を入れた時点で**、登録日・状態（`売出中`）・売出日が自動で入ります。
売出日が実際にはもっと前なら、そこだけ書き換えてください。

### 自動で計算される列（手で触らない）

| 列 | 中身 |
| --- | --- |
| 当初価格(万円) | 初めて価格を入れたときの値を保持。値下げ率の基準になります |
| 坪単価(万円) | 価格 ÷（面積 ÷ 3.305785）。成約後は成約価格で計算し直します |
| 経過日数 | 売出日から今日まで。成約済みなら「売出〜成約」の日数 |
| 値下げ率(%) | （当初価格 − 現在の売出価格）÷ 当初価格 |
| 乖離率(%) | （成約価格 − 当初価格）÷ 当初価格 |

### 日々の運用は2アクションだけ

1. **値下げを見つけたら、売出価格のセルを書き換える。**
   それだけで `価格履歴` シートに「いつ・いくらから・いくらへ・何%」が1行たまり、
   値下げ率も更新されます。当初価格を自分で控えておく必要はありません。
2. **決まったら、状態を `成約` にして成約価格を入れる。**
   成約日は自動で今日が入ります（違う日なら書き換えてください）。

状態は `売出中` / `商談中` / `成約` / `取下` の4つを想定しています。

## 週次メールで出るもの

- 成約（月×区の件数・平均坪単価・中央値・最高価格）
- 売出中の件数
- **90日以上動いていない物件** の一覧 … 高級帯は動きが遅いので90日が一つの目安
- **値下げがあった物件** の一覧 … 在庫が膨らんだときに最初にここへ出ます
- **直近30日に成約した物件** … 当初価格・成約価格・乖離率・売出から成約までの日数

### 乖離率が効いてくる理由

`乖離率` は「最初に付けた売出価格から、実際いくらで決まったか」です。
これを半年ためると、**自社の価格設定が強気すぎるのか妥当なのかが数字で出ます。**
売主への価格提案のときに、この実績ほど説得力のある材料はありません。

---

## 注意点

- **成約データは遅れます。** 不動産情報ライブラリの公表は四半期ごとで、
  直近の取引が載るまで数カ月かかります。「先月売れたもの」をここで知ることはできません。
  足元の動きは `売出ウォッチ` 表の側で押さえてください。
- **APIは連続実行しない。** 国交省から間隔を空けるよう案内が出ています。
  スクリプト側で1.2秒待つようにしてありますが、手で連打しないでください。
- **重複は入りません。** 同じ四半期を2回取り込んでも、既にある行は飛ばします。
  過去分をまとめて入れたいときは `importTransactionsRange(2020, 1, 2026, 1)` のように
  引数付きで実行してください（Apps Script のエディタから引数を渡す場合は、
  一時的に呼び出し用の関数を作るのが簡単です）。
- **社内情報は書かない。** 宛先アドレス・スプレッドシートIDはスクリプトプロパティ側で
  管理し、このリポジトリには置かない方針です。
