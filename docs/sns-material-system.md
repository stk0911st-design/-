# SNS素材 自動運用の仕組み

社員がメール・Slack・ドライブで送った写真や動画を「受付」フォルダに集め、
週2回、Claude が投稿案を作って Slack に届け、担当者が確認して投稿し、
使った素材を「使用済み」へ移す運用。

> 実際のフォルダID・宛先・氏名・チャンネル名は、このリポジトリに書かない。
> `<INTAKE_FOLDER_ID>` `<USED_FOLDER_ID>` `<SLACK_CHANNEL>` のようなプレースホルダで示す。
> 実値は Apps Script のスクリプトプロパティ、または Claude のルーティン設定で管理する。

## 全体の流れ

```
社員 ─┬─ メール（件名に【SNS素材】）──→ Apps Script ──→ ドライブ「01_受付（未使用）」
      ├─ ドライブへ直接アップロード ─────────────────→ 同上
      └─ Slack（リンクを共有） ─────────→ 担当者が「01_受付」へ移す
                                                    │
                    週2回 Claude ルーティン（火・金 11:00 JST）
                                                    ▼
                          素材を読む → 投稿案を作る → Slack の確認用チャンネルへ送る
                                                    │
                       主担当が確認 → 各SNS・ホームページへ投稿 → ✅ とURLを返す
                                                    │
                       次回のルーティンが ✅ を確認 → 使った素材を「02_使用済み」へ移す
```

## 役割

| 役割 | 内容 |
| --- | --- |
| 全社員 | 素材を送る（メールまたはドライブ） |
| 主担当 | 投稿案の確認、各SNS・ホームページへの投稿、✅ とURLの返信 |
| 補佐 | 主担当の補助。確認用チャンネルとメールのCCに入る |
| 社長 | 👀 で確認。内容の最終判断 |
| Claude | 素材の整理、投稿案の作成、使用済みへの移動 |

## ドライブのフォルダ構成

```
SNS素材（営業担当A・全社）
├─ 01_受付（未使用）        … 送られた素材がここに溜まる
├─ 02_使用済み              … 投稿に使った素材を移す（消さない）
└─ 03_完成（動画・加工後）   … 編集後の動画・画像
```

## 素材の送り方（社員向け）

1. **メール**: 件名の先頭に `【SNS素材】` を付け、写真・動画を添付して、受付用のアドレスへ送る。
   本文に「いつ・どこ・何の写真か」を一言書くと、投稿案の質が上がる。
2. **ドライブ**: 「01_受付（未使用）」へ直接アップロードする（スマホの Drive アプリでよい）。
3. **Slack**: 動画などはドライブにアップロードし、リンクを確認用チャンネルへ貼る。

送らないもの: 金額、お客様の情報、物件の部屋番号、個人の連絡先、他の人の顔がはっきり写った写真。

## 導入手順

### 1. メール → ドライブ（Apps Script）

1. 受付用の Google アカウントで [script.google.com](https://script.google.com) を開き、新しいプロジェクトを作る。
2. `gas/SnsMaterialIntake.gs` の内容を貼り付ける。
3. 「プロジェクトの設定 → スクリプト プロパティ」に次を追加する。

   | プロパティ | 値 |
   | --- | --- |
   | `INTAKE_FOLDER_ID` | 「01_受付（未使用）」フォルダのID |
   | `USED_FOLDER_ID` | 「02_使用済み」フォルダのID |
   | `SUBJECT_KEY` | （任意）件名の目印。既定は `【SNS素材】` |

4. `previewSaveMailMaterials` を実行し（初回は権限の承認が必要）、実行ログで保存予定のファイルを確認する。保存はされない。
5. 問題なければ「トリガー → トリガーを追加」で次を設定する。
   - 実行する関数: `saveMailMaterials`
   - イベントのソース: 時間主導型 → 分ベースのタイマー → 15分おき

### 2. 週2回の投稿案づくり（Claude ルーティン）

- 曜日・時刻: 火・金 11:00 JST（cron は UTC なので `0 2 * * 2,5`）。会社休日（水・日）は避ける。
- プロンプトの骨子:

  1. 前回の投稿案のメッセージを `<SLACK_CHANNEL>` で読み、✅ が付いたものに使った素材を `02_使用済み` へ移す。
  2. `01_受付（未使用）` の素材とメモを読む。
  3. 素材が無ければ「素材がありません。送ってください」とだけ投稿して終わる（投稿案を作り話で作らない）。
  4. 素材があれば、Instagram・X・Facebook・ホームページ用の投稿案を作り、`<SLACK_CHANNEL>` に送る。使う素材のファイル名とURLを必ず書く。
  5. 担当者の名前は出さず「営業担当A」と書く。金額・顧客・物件の情報、他人の顔が分かる写真は使わない。
  6. 投稿案には「未投稿」と書く。投稿はしない。

- Slack の確認用チャンネルは非公開にし、主担当・補佐・社長だけを入れる。

### 3. 投稿（主担当）

1. チャンネルの投稿案を確認し、直すところがあればスレッドに書く。
2. Instagram → X → Facebook → ホームページの順に投稿する。
3. 投稿案のメッセージに ✅ を付け、スレッドに各投稿のURLを貼る。
4. 社長が確認したら 👀 を付ける。

## できないこと・注意

- Claude から Instagram・X・Facebook・ホームページへ直接投稿することはできない。投稿は主担当が行う。
- Slack に貼られた写真・動画のファイルを、Claude がドライブへ自動保存することはできない（リンク共有か直接アップロードにする）。
- メールの受付は、スクリプトを動かすアカウントに届いたメールだけが対象。
- 「使用済み」へ移すのは、✅ が付いた投稿案に書かれた素材だけ。✅ が無ければ移さない。
- 音楽は各SNSの音源ライブラリか、商用利用できる音源だけを使う。
- ファイルは削除しない。間違えて移したときは、手で「受付」へ戻す。

## 確認チェックリスト（初回）

- [ ] `previewSaveMailMaterials` のログで、想定どおりのファイルが対象になった
- [ ] 送信テストのメールが、受付フォルダに保存された
- [ ] 同じメールが二重に保存されない（ラベルが付く）
- [ ] 確認用チャンネルに、主担当・補佐・社長だけが入っている
- [ ] ルーティンの初回は、投稿案が Slack に届くことだけを確認した（実際の投稿は人が確認してから）
