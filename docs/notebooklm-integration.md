# NotebookLM 連携（営業日報ナレッジ）

営業日報の入力内容を NotebookLM に読ませ、「今週の架電は誰が多い？」「先月と比べてどう？」
といった質問に答えられるようにするための連携です。

## 全体像

```
日報カウンター（スプレッドシート）
        │
        │  Claude のルーティン（平日 夜）が読み取り・整形
        ▼
Google ドライブ ／ NotebookLM_営業日報 フォルダ
        ├─ 00_営業日報 データ定義
        ├─ 営業日報ログ_YYYY-MM （当月分。毎晩作り直し）
        └─ 営業日報ログ_YYYY-MM （前月までの分。確定後は更新しない）
        │
        │  NotebookLM の自動同期（数分おき）
        ▼
NotebookLM のノートブック「営業日報」
```

NotebookLM は Google ドライブのフォルダをソースに指定でき、フォルダ内のファイルが
追加・更新・削除されると数分おきに自動で反映されます（2026年5月以降の機能）。
そのため **こちら側はドライブにファイルを置くだけ**で、NotebookLM の操作は初回設定の1回で済みます。

## なぜスプレッドシートを直接ソースにしないのか

スプレッドシートも NotebookLM のソースにできますが、生データ表は
`report｜2026-08-24｜島田` / `{"call":1,...}` という JSON 文字列のため、
そのまま読ませても集計や比較の精度が出ません。
また **カウンターが週単位の累計値**である点を知らないと、NotebookLM は数字を
日別の実績と誤解します。

そこで、Claude が「人が読んで分かる日本語のログ」に整形してから渡します。
数字の意味・注意点は `00_営業日報 データ定義` に書いてあり、NotebookLM は
それも合わせて読むため、誤読が起きにくくなります。

## ファイル構成

| ファイル | 役割 | 更新 |
| --- | --- | --- |
| `00_営業日報 データ定義` | 項目の意味、担当者一覧、週累計であることの注意、質問のしかた | 担当者の増減時など、必要なときだけ |
| `営業日報ログ_YYYY-MM` | その月の日別ログ・週次サマリ・月次サマリ | 当月分のみ、平日の夜に作り直し |

当月分のドキュメントは **毎回スプレッドシートから全期間を作り直します**。
前回のドキュメントを読んで継ぎ足す方式にはしていません。継ぎ足すと、ずれや
取りこぼしが積み重なるためです。正は常にスプレッドシートです。

## 初回セットアップ

### 1. ドライブ側（Claude が実施済み／未実施なら Claude に依頼）

1. マイドライブに `NotebookLM_営業日報` フォルダを作る
2. `00_営業日報 データ定義` を作る（内容は `docs/templates/notebooklm-data-dictionary.md`）
3. 当月・前月の `営業日報ログ_YYYY-MM` を作る（体裁は `docs/templates/notebooklm-monthly-log-template.md`）

### 2. NotebookLM 側（ご自身の操作。5分ほど）

1. [notebooklm.google.com](https://notebooklm.google.com/) を、スプレッドシートを見られる
   Google アカウントで開く
2. **新規作成** でノートブックを作り、名前を `営業日報` にする
3. **ソースを追加 → Google ドライブ** で `NotebookLM_営業日報` **フォルダ**を選ぶ
   - ファイル個別ではなく、フォルダごと選ぶのがポイントです。以後に増えるファイルも
     自動で入ります
   - フォルダ選択が出ない場合は、フォルダ内のファイルを個別に追加してください
     （その場合、翌月の新ファイルは手動で追加が必要です）
4. ソース一覧で **自動同期（Auto-sync）が ON** になっていることを確認する
5. 「今日の日報入力状況を教えて」と聞いて、答えが返れば完了

### 3. 更新の自動化

平日の夜に Claude のルーティンで当月分を作り直します。
設定内容は `docs/notebooklm-routine-prompt.md` を参照。

## 聞けること（質問例）

- 今週、架電がいちばん多い担当者は？
- 先週と今週で、訪問・面談の件数はどう変わった？
- 今月まだ一度も日報を入力していない担当者は？
- コメント欄に書かれた内容をまとめて、気になる案件を挙げて
- 8月と9月の合計を担当者別に比較して

※ NotebookLM は**ソースに書かれていることしか答えません**。
当月分の反映は夜のルーティン実行後になるため、その日の日中の入力は
翌朝以降に反映されます。

## 注意点

- **社外秘です。** ノートブックもドライブのフォルダも共有しないでください。
  NotebookLM のノートブックを共有すると、ソースの中身も相手に見えます。
- **数字は週累計です。** 日別の増減は出せません（日報アプリ側が週単位で
  カウントしているため）。日別が必要なら日報アプリの保存方式の変更が必要です。
- **当月分のドキュメントは毎晩置き換わります。** 古いほうはドライブのゴミ箱に入り、
  30日間は復元できます。ドキュメントに手で書き足した内容は次の実行で消えるため、
  メモを残したい場合はフォルダ内に別ファイルを作ってください（それも自動で
  NotebookLM のソースになります）。
- ソース数の上限（無料プランで50件）に注意。月1ファイル方式なので通常は問題ありませんが、
  数年運用する場合は古い年の分をフォルダの外へ移してください。
