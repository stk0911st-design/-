# 毎晩23時 前向きメッセージメール

寝る前に読んで、腹の底からやる気が湧き上がるための短いメッセージを毎晩自動でメール送信します。

## 仕様

| 項目 | 内容 |
| --- | --- |
| 配信タイミング | 毎日 23:00（JST） |
| cron（UTC） | `0 14 * * *` |
| 宛先 | 本人のメールアドレス（設定値として管理） |
| 本文の長さ | 日本語 200〜300文字 |
| 送信方法 | 自動送信（本人宛のため毎回の確認は不要） |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |

## 本文のテーマ

毎晩、以下のいずれかを軸に切り口を変えて生成します。

- 潜在意識が全てを決める／寝る前の言葉が潜在意識に刻まれる
- 必ずできる、自分は必ず成し遂げられる
- 前向きな心が結果を変える（脳科学的な文脈で）
- マクドナルド創業者レイ・クロックが毎晩寝る前に自己啓発の音声を流して眠っていたという逸話
- 明日の自分はもっと強い／眠っている間に脳が答えを用意してくれる

## 文体

方針は「信念的に、湧き上がるように」。慰めや励ましではなく、**信条の宣言**として書きます。

- 一人称の宣言文（「私は必ずできる」）を冒頭に置き、最後にもう一度返して畳み込む
- 短文を刻んで積み上げる。リズムで熱が上がっていくように
- 言い切る。「〜かもしれない」「〜してみよう」は使わない
- 否定で挟んで肯定を立てる（「才能ではない。決意だ。」）
- 身体感覚のある言葉を混ぜる（「腹の底から」など）
- 慰め・共感・自己憐憫に流れない。読んだ人が拳を握って眠れるように
- 締めは就寝への短い命令形（「ぐっすり眠れ。明日のあなたは、今日より強い。」）

件名は「今夜のひとこと 〜（その日の宣言を短く）〜」の形で毎回変えます。

## 配信例

> 件名：今夜のひとこと 〜私は必ずできる〜
>
> 私は必ずできる。この一行を、今夜の最後の言葉にしてほしい。
>
> 理由づけはいらない。潜在意識は理屈を聞かない。ただ繰り返された言葉を、そのまま事実として受け取る。
> だから寝る前の一言が、明日のあなたの動きを決める。
>
> レイ・クロックは毎晩、自己啓発の音声を流したまま眠った。彼が最初の店を開いたのは52歳。
> 才能ではない。眠りの直前に、自分に何を聞かせるかを選び続けただけだ。
>
> 前向きさは気分ではない。脳の使い方だ。できると決めた脳は、できる道を探し始める。
> 今この瞬間から、それは始まっている。
>
> 私は必ずできる。腹の底から、もう一度。ぐっすり眠れ。明日のあなたは、今日より強い。

## 文体（最重要）
「信念的に、湧き上がるように」。慰めや励ましではなく、信条の宣言として書く。

- **一人称の宣言文を軸に置く。** 「私は必ずできる」「私は必ず成し遂げる」のような短い断言を、
  冒頭に置き、最後にもう一度返す（同じ言葉で挟んで畳み込む）。
- **短文を刻んで積み上げる。** 一文を短く切り、次の文で強め、次で言い切る。
  リズムで熱が上がっていくように。だらだらした複文にしない。
- **言い切る。** 「〜かもしれない」「〜だと思う」「〜してみよう」は禁止。
  「〜だ」「〜である」「〜しろ」で言い切る。理由を長く説明せず、断定を重ねる。
- **否定で挟んで肯定を立てる。** 「才能ではない。決意だ。」「気分ではない。脳の使い方だ。」
  のような対比を使って、言葉に芯を通す。
- **体温のある言葉を混ぜる。** 「腹の底から」「血が通う」「火を落とすな」など、
  身体感覚のある語を使う。抽象語だけで終わらせない。
- 慰め・共感・自己憐憫に流れないこと。読んだ人が拳を握って眠れるように。
- 最後は就寝への短い命令形で締める（例：「ぐっすり眠れ。明日のあなたは、今日より強い。」）。

## 件名
「今夜のひとこと 〜（その日の宣言を短く）〜」の形で毎回変える。宣言そのものを件名にしてもよい。

## その他

- レイ・クロックに触れる場合、事実関係は「毎晩寝る前に自己啓発の音声を流して眠った」
  「最初の店を開いたのは52歳」の範囲にとどめ、経歴を推測で盛らない。

## 運用メモ

- cron は UTC で書きます。日本時間 23:00 は UTC 14:00 で、同じ日付のままです。
  曜日指定がないため日付のずれは発生しません（朝8時配信の日報メールとは違う点）。
- **起動モードは「既存セッションを継続」でなければ動きません。**
  毎回新しいセッションを作る方式（`create_new_session_on_fire`）で試したところ、
  起動したセッションに Gmail コネクタが引き継がれず、送信も下書き作成もできませんでした。
  ルーティン作成時にも「このルーティンはコネクタを保存していないため、
  起動されるセッションはコネクタツールなしで動く」という警告が出ます。
  そのため Gmail を保持しているセッションを起こす方式で登録しています。
  営業日報メール（`docs/routine-prompt.md`）と同じ理由・同じ方式です。
- 上記の制約から、バインド先のセッションが失われるとルーティンは送信できなくなります。
  メールが届かなくなった場合は、Gmail コネクタを持つセッションから作り直してください。
- 文体は一度「穏やかに語りかける調子」で運用したあと、より信念的・湧き上がる方向へ振り直しました。
  さらに調整する場合はこのファイルの「文体」節とルーティンのプロンプトを合わせて更新してください。
