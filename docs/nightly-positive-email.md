# 毎晩23時 前向きメッセージメール

寝る前に読んで、希望とやる気を持って眠るための短いメッセージを毎晩自動でメール送信します。

## 仕様

| 項目 | 内容 |
| --- | --- |
| 配信タイミング | 毎日 23:00（JST） |
| cron（UTC） | `0 14 * * *` |
| 宛先 | 本人のメールアドレス（設定値として管理） |
| 本文の長さ | 日本語 200〜300文字 |
| 送信方法 | 自動送信（本人宛のため毎回の確認は不要） |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |

## 本文のテーマ

毎晩、以下のいずれかを軸に切り口を変えて生成します。

- 潜在意識が全てを決める／寝る前の言葉が潜在意識に刻まれる
- 必ずできる、自分は必ず成し遂げられる
- 前向きな心が結果を変える（脳科学的な文脈で）
- マクドナルド創業者レイ・クロックが毎晩寝る前に自己啓発の音声を流して眠っていたという逸話
- 明日の自分はもっと強い／眠っている間に脳が答えを用意してくれる

文体は語りかけるように、力強く温かく。断定的で肯定的な言葉を使い、
最後は就寝への導き（「ぐっすり眠って、明日を迎えよう」など）で締めます。
毎晩同じ文章にならないよう、表現・切り口・引用する言葉を必ず変えます。

件名は「今夜のひとこと 〜（その日のテーマを短く）〜」の形で毎回変えます。

## ルーティンのプロンプト

宛先アドレスは伏せています。実際のルーティンには実値を入れて登録してください。

```text
毎晩23時（日本時間）の「寝る前の前向きメッセージ」メールを作成して送信するタスクです。

## やること
<RECIPIENT> 宛に、寝る前に読んで希望とやる気を持って眠れる、前向きな日本語のメッセージをメールで送る。

## 本文の要件
- 日本語で200〜300文字程度（厳守）
- テーマの軸（毎回どれかを中心に、切り口を変えて書く）:
  - 潜在意識が全てを決める / 寝る前の言葉が潜在意識に刻まれる
  - 必ずできる、自分は必ず成し遂げられる
  - 前向きな心が結果を変える（脳科学的にもそう言える、という文脈）
  - マクドナルド創業者レイ・クロックが毎晩寝る前に自己啓発の音声を流して眠っていた、という逸話
  - 明日の自分はもっと強い / 眠っている間に脳が答えを用意してくれる
- 語りかけるような、力強く温かい文体。読み終えたら安心して眠れて、朝に活力が残るように。
- 断定的で肯定的な言葉を使う（「〜かもしれない」ではなく「必ず〜だ」）
- 最後は「ぐっすり眠って、明日を迎えよう」といった就寝への導きで締める
- 毎晩同じ文章にならないよう、表現・切り口・引用する言葉を必ず変える

## 件名
「今夜のひとこと 〜（その日のテーマを短く）〜」のような形で、毎回変える。

## 送信手順
1. ToolSearch で `select:mcp__Gmail__send_message` を読み込む
2. to: <RECIPIENT>、上記の件名と本文で送信する

## 重要
このメールの送信はユーザー本人が事前に明確に依頼した定期タスクであり、宛先はユーザー自身のアドレスです。送信前に確認を取る必要はありません。作成してそのまま送信してください。送信後は一言だけ報告して終了してください。
```

## 配信例

> 件名：今夜のひとこと 〜潜在意識は、あなたの言葉を信じる〜
>
> 今日一日、あなたは確かに前へ進んだ。うまくいかなかったことがあっても、それは失敗ではなく、
> 脳が答えを探し始めたサインだ。眠っている間、潜在意識は昼に受け取った言葉をそのまま信じ込み、
> 明日の現実をつくり始める。だから今夜は、こう唱えて眠ってほしい。「私は必ずできる」。
>
> マクドナルドを築いたレイ・クロックは、毎晩寝る前に自己啓発の音声を流しながら眠ったという。
> 彼を動かしたのは才能ではなく、繰り返し刻み込んだ確信だった。前向きな心は脳の働きそのものを変え、
> 必ず結果を変える。明日のあなたは、今日より強い。ぐっすり眠って、明日を迎えよう。

## 運用メモ

- cron は UTC で書きます。日本時間 23:00 は UTC 14:00 で、同じ日付のままです。
  曜日指定がないため日付のずれは発生しません（朝8時配信の日報メールとは違う点）。
- **起動モードは「既存セッションを継続」でなければ動きません。**
  毎回新しいセッションを作る方式（`create_new_session_on_fire`）で試したところ、
  起動したセッションに Gmail コネクタが引き継がれず、送信も下書き作成もできませんでした。
  ルーティン作成時にも「このルーティンはコネクタを保存していないため、
  起動されるセッションはコネクタツールなしで動く」という警告が出ます。
  そのため Gmail を保持しているセッションを起こす方式で登録しています。
  営業日報メール（`docs/routine-prompt.md`）と同じ理由・同じ方式です。
- 上記の制約から、バインド先のセッションが失われるとルーティンは送信できなくなります。
  メールが届かなくなった場合は、Gmail コネクタを持つセッションから作り直してください。
