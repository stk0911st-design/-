# 中古マンション市況トラッカー 導入手順

毎日18:00に東日本レインズの月例速報をチェックし、スプレッドシートに蓄積して
メールで通知する Apps Script（`gas/MansionMarketTracker.gs`）の設定手順です。

## この仕組みで取れるもの / 取れないもの

| | 取得可否 | 粒度 |
| --- | --- | --- |
| 成約件数 | ○ | 月次 × 東京都区部（23区まとめ） |
| 新規登録件数（新たに売り出された数） | ○ | 同上 |
| 在庫件数（月末時点の売出中件数） | ○ | 同上 |
| **23区の区別内訳** | **×** | レインズが公表していない |
| **日次の変動** | **×** | 公表が月1回のため |

背景と他の選択肢は `docs/tokyo-mansion-tracker-feasibility.md` を参照。
（区別データが必要になった場合は、国土交通省「不動産情報ライブラリ」API
＝四半期・区別 を後から追加する形で拡張できます）

## 手順

### 1. 蓄積用スプレッドシートを作る

Google ドライブで新規スプレッドシートを作成し、名前を「23区マンション指標」等にします。
シート（`monthly_reins` / `daily_log` / `raw_text`）はスクリプトが自動作成するので、
手作業での準備は不要です。

### 2. Apps Script を作る

1. そのスプレッドシートで「拡張機能 → Apps Script」。
2. `gas/MansionMarketTracker.gs` の内容を貼り付けて保存。
3. 左メニュー「サービス（＋）」から **Drive API** を追加する
   （識別子は `Drive`、バージョンは v3）。PDFをテキスト化するのに必要です。

### 3. スクリプトプロパティを設定する

「プロジェクトの設定 → スクリプト プロパティ」に追加します。

| プロパティ | 値 | 必須 |
| --- | --- | --- |
| `RECIPIENT` | 送信先メールアドレス | ○ |
| `CC` | CCアドレス（カンマ区切り） | |
| `SPREADSHEET_ID` | 別ファイルを蓄積先にする場合のみ | |
| `SAVE_RAW_TEXT` | `true`（初回の動作確認時に推奨） | |
| `FIELD_ORDER` | 数値の並び順の補正（下記参照） | |

※ アドレス等はリポジトリに置かず、必ずこちらで管理してください。

### 4. 初回の取り込みと確認（重要）

レインズのPDFは公表回によってレイアウトが変わることがあるため、
**初回だけ抽出結果を目視確認してください。**

1. `SAVE_RAW_TEXT` を `true` にした状態で `ingestOnly` を実行する。
   （初回実行時に権限の承認を求められます）
2. `monthly_reins` シートを開き、`抽出結果` 列が `OK` になっているか、
   `成約件数` `新規登録件数` `在庫件数` の値がPDFと一致しているかを確認する。
3. **値がずれている場合**：`抽出値(生)` 列に、拾った数値が拾った順のまま入っています。
   PDFの実際の並び順に合わせて `FIELD_ORDER` を設定すれば、コードを変えずに直せます。

   例）PDFの並びが「成約件数 / 前年比 / ㎡単価 / 前年比 / 成約価格」だった場合:
   ```
   FIELD_ORDER = contracts,contractsYoY,unitPrice,skip,price,skip,skip,skip
   ```
   使えるキー: `contracts` `contractsYoY` `newListings` `newListingsYoY`
   `stock` `stockYoY` `unitPrice` `price` `skip`
4. 直したら `monthly_reins` の該当行を手で消してから `ingestOnly` を再実行する
   （スクリプトは自動では行を消しません）。
5. 確認できたら `SAVE_RAW_TEXT` を `false` に戻す。

### 5. 文面を確認する

`previewMansionMarketMail` を実行し、実行ログで本文を確認します（**送信はされません**）。

### 6. トリガーを設定する

「トリガー → トリガーを追加」で以下を設定します。

- 実行する関数: `sendMansionMarketMail`
- イベントのソース: 時間主導型
- 日付ベースのタイマー: **午後6時〜7時**

## 動作

- 毎日18時台に実行され、未取得の公表月があれば取り込みます（通常は月1回のみ増えます）。
- 新しい公表が無い日も、最新値と直近12か月の推移をメールで送ります。
- 取り込み済みの行は上書き・削除しません（追記のみ）。
- 実行のたびに `daily_log` へ記録が残ります。抽出に問題があった日は状態が `要確認` になり、
  メール末尾にも理由が表示されます。

## テスト

パーサとメール生成のロジックは Node で単体テストできます。

```
node gas/tests/mansion-tracker.test.js
```

Apps Script の API はテスト内でスタブ化しているため、ネットワーク接続は不要です。
