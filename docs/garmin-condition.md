# ガーミンの毎日のコンディションを蓄積する

「ガーミンのアプリとつなげて、毎日のコンディションを蓄積して調べられるか」を調べた結果と、
採用した方式のまとめ。（調査日：2026-09-05）

## 結論

完全自動の連携は個人では現実的に組めない。
**入力だけ手で行い、蓄積・集計・分析は自動**という半自動方式にする。

## 方式の比較

| 方式 | 可否 | 内容 |
| --- | --- | --- |
| ① Garmin 公式 Health API | ❌ | Connect Developer Program は法人格が必須。「自分のデータが欲しい」という個人利用の申請は却下される。取得できる項目（睡眠・ストレス・Body Battery・HRV・安静時心拍の日次サマリー）は理想的だが、入口で止まる |
| ② 非公式ライブラリ（python-garminconnect など） | △ | Garmin の ID/パスワードでスマホアプリを装って取得する。2026年3月に Garmin がボット対策を強化して大半のツールが一度停止し、garth は開発終了。現在は復旧しているが、いつ止まるか読めない。データセンターのIP（GitHub Actions など）は弾かれやすく、常時稼働のPCが要る。規約もグレー |
| ③ Health Connect 経由（Android） | △ | Garmin Connect → Health Connect の一方通行で送れるが、歩数・安静時心拍・睡眠の集計値程度。Body Battery や睡眠スコアは来ない |
| ④ 全データエクスポート | ⭕ | Garmin Connect の「データのエクスポート」で過去分を一括で取得できる。過去データの初期取り込み向き。日次運用には不向き |
| ⑤ 半自動（採用） | ⭕ | 毎朝アプリの数値を入力画面に入れる（20秒）。以降の蓄積・平均・比較・検索は自動 |

②が止まっても、⑤なら記録が途切れない。まず⑤で貯め始めて、必要になったら②を足す形にできる。

## 記録する項目

シート名は `コンディション`。1日1行で、同じ日付を入れ直すと上書きされる。

| 列 | 内容 | ガーミンでの見どころ |
| --- | --- | --- |
| 日付 | 記録の対象日 | — |
| 曜日 | 自動 | — |
| 睡眠スコア | 0-100 | 睡眠 → スコア |
| 睡眠時間(h) | 例 6.5 | 睡眠 → 合計 |
| Body Battery(起床) | 0-100 | Body Battery → 起床時の値 |
| Body Battery(最低) | 0-100 | Body Battery → 前日の最低値 |
| HRV | ms | HRVステータス → 夜間平均 |
| 安静時心拍 | bpm | 心拍数 → 安静時 |
| ストレス平均 | 0-100 | ストレス → 前日の平均 |
| 歩数 | 前日の歩数 | — |
| 体感(1-5) | 主観。1=最悪 / 5=絶好調 | ガーミンにない、自分の感覚 |
| メモ | 体調・気になること | — |
| 記録日時 | 自動 | — |

数値はすべて任意。入れられるものだけ入れれば、平均はある分だけで計算される。
**体感(1-5) は必ず入れる。**ガーミンの数値と主観のズレが、あとで一番役に立つ。

## 使い方（こちらが用意したページ）

設置作業は不要。次のURLを開くだけで使える。**自分だけが開ける非公開ページ**で、記録もこのページに紐づいて保存される。

https://claude.ai/code/artifact/5af1f8a8-5269-4c1c-b36d-890aee7e6510

- スマホのブラウザで開いて、ホーム画面に追加しておく（毎朝そこから開く）
- ガーミンの数値を入れて「保存する」。同じ日付を入れ直すと上書きされる
- 下に「直近7日の平均（前週比つき）」「推移グラフ」「記録一覧」が出る
- 記録は Claude（私）からも読めるので、朝夜のルーティンや分析にそのまま使える

ページの元になっているHTMLは `artifact/condition-log.html`。作り直すときはこれを直す。

## 別案：スプレッドシートで持ちたい場合の導入手順

記録をスプレッドシート側に置きたくなったとき用に、Apps Script 版も用意してある。
上のページを使うなら、この節は読み飛ばしてよい。

1. Google ドライブで新しいスプレッドシートを作る（名前は「コンディション記録」など）。
   ※ 会社の日報スプレッドシートとは分ける。個人の健康データなので混ぜない。
2. そのスプレッドシートで「拡張機能 → Apps Script」を開く。
3. スクリプトファイルを2つ作る。
   - `ConditionLog.gs` … `gas/ConditionLog.gs` の内容を貼る
   - `ConditionForm.html` … 「＋ → HTML」で作成し、`gas/ConditionForm.html` の内容を貼る
     （ファイル名は拡張子を除いて `ConditionForm` にする）
4. 関数 `selfTest` を1回実行して、`コンディション` シートが作られることを確認する。
   確認できたらテスト行は消してよい。
5. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」で公開する。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **自分のみ**
6. 出てきたURLをスマホのホーム画面に追加する。これが毎朝の入力画面になる。

### （任意）朝のリマインドメール

7. 「プロジェクトの設定 → スクリプト プロパティ」に追加する。

   | プロパティ | 値 |
   | --- | --- |
   | `REMINDER_TO` | リマインドの宛先メールアドレス |
   | `FORM_URL` | 手順5で出たウェブアプリのURL |

8. 「トリガー → トリガーを追加」で設定する。
   - 実行する関数: `sendConditionReminder`
   - イベントのソース: 時間主導型 → 日付ベースのタイマー → 午前7時〜8時

   その日の記録がすでに入っていれば送信されない。

## 調べ方

入力画面の下に、**直近7日の平均**（その前の7日との増減つき）と**記録一覧**が出る。
矢印の色は「良い方向／悪い方向」で分けてある（安静時心拍とストレスは下がると良い扱い）。

それ以上の分析は、スプレッドシートをそのまま使うか、私（Claude）に聞いてください。例：

- 「先月と今月で睡眠スコアの平均どう変わった？」
- 「体感が2以下だった日の共通点は？」
- 「Body Battery が低い日と、商談件数の多い日は重なってる？」
- 「HRVが落ち始めたのはいつから？」

夜のルーティン（日記作成）でも、その日のコンディションを反映させます。

## 過去データを取り込みたいとき

Garmin Connect のウェブ版から「アカウント情報 → データのエクスポート」で全データを申請すると、
数日後にダウンロードリンクがメールで届く。中の日次サマリー（JSON）から必要な項目だけ抜き出して、
`コンディション` シートに流し込める。やるときは声をかけてください、変換スクリプトを用意します。
