# 事務パイプライン（毎日の事務まとめ） 仕様

事務担当の1日の仕事を全員分まとめて PDF にし、毎晩、事務の全員と代表・役員へ届けます。
これまで Slack の「事務パイプライン」チャンネルで手作業（AI秘書の代筆）で出していたものを、
Claude の定期実行（スケジュールされたタスク）で毎日自動で出すようにしたものです。

あわせて、**案件の期限リマインド**と**書類の提出チェック**も同じ PDF に入れます。

使うファイル：`tools/html-to-pdf.js`（HTML → PDF 変換）

## しくみ

| 項目 | 内容 |
| --- | --- |
| 動く日 | 会社の営業日（月・火・木・金・土）。水曜・日曜は会社休日なので動かない |
| 動く時刻 | 19:23（JST）。夕礼（17:30 ごろ）と退勤の後 |
| 起動 | 毎回あたらしいセッションを起動（このリポジトリが入った状態で始まる） |
| 使うコネクタ | Slack・Gmail・Google ドライブ・Google カレンダー |
| 出すもの | ① PDF（A4・2〜3ページ） ② メール（PDF 添付） ③ Slack への投稿 ④ ドライブへの PDF 保存 |

## 材料

| 材料 | 何を拾うか |
| --- | --- |
| Slack「朝礼夕礼」チャンネル | 朝礼・夕礼の録画（文字起こし・要約）のコメント。誰が何を話したか |
| Slack「社長指示_<名前>」チャンネル | 各担当の **3行報告**（① やったこと ② 明日やること ③ 困っていること）。朝の「今日の予定」スレッドへの返信 |
| Slack「事務パイプライン」チャンネル | その日の依頼と、事務からの返信（:eyes: → :white_check_mark:） |
| 勤務表（日報カウンターの shifts） | その日 出勤だった人／お休みだった人 |
| Google カレンダー | 決済・契約・期限などの予定（期限リマインド用） |
| Google ドライブの案件フォルダ | 書類がそろっているか（書類チェック用） |

## PDF の中身

1. **きょうの「ありがとう」** ― 出勤した事務の方ひとりずつ、その日にやった仕事を具体的に書いてお礼を言う。
   最後に「今日は皆さんこれだけ頑張りました。明日もよろしくお願いします。」で締める。
2. **朝礼・夕礼のコメント** ― 録画から拾えた話の要点（担当ごと）。
3. **3行報告** ― 担当ごとの ① やったこと ② 明日やること ③ 困っていること。出していない人は「まだ届いていません」とだけ書く。
4. **案件の期限リマインド** ― 今日から14日以内の決済・契約・書類の期限を日付順に。7日以内は目立たせる。
5. **書類の提出チェック** ― 14日以内に決済・契約がある案件について、案件フォルダに必要な書類
   （登記簿謄本・公図・測量図・重要事項説明書・売買契約書・本人確認書類など）があるか。足りないものを一覧にする。
6. **明日の一歩** ― 明日、誰が何をするか（3行報告の ② と、残っている依頼から）。

## 必ず守ること

- **金額は一切書かない**（売上・粗利・預金残高・借入残高・買付金額・査定額・振込額・目標の数字）。
- **お客様の名前は書かない**。物件は地名や社内の呼び名で書く。
- **人どうしを比べない**。件数の表・順位・点数・評価の言葉は入れない（個人の評価は代表だけが扱う）。
  このまとめは「ありがとう」と事実だけ。
- 読み取れなかったものは推測で埋めず、「確認できませんでした（不明）」と書く。
- お休みの人に督促を書かない。勤務表で「休み」「✖」「空欄」の人は「ゆっくり休んでください」だけ。
- 宛先・投稿先は決められた所だけ。それ以外には送らない。

## 宛先

実際のアドレスはスケジュールされたタスクの設定（プロンプト）にだけ書き、このリポジトリには置きません。

| 区分 | 宛先 |
| --- | --- |
| メール To | 事務担当（社用メールがある人）`<JIMU_RECIPIENTS>` |
| メール Cc | 役員 `<OFFICER>`、代表のアドレスすべて `<CEO_ADDRESSES>` |
| Slack | 「事務パイプライン」チャンネル `<CHANNEL_ID>`（社用メールがない人にもここで届く） |
| ドライブ | 毎日の PDF の保管フォルダ `<FOLDER_ID>`（閲覧のみ） |

ファイル名：`事務パイプライン_YYYY-MM-DD(曜).pdf`

## PDF の作り方（定期実行の中でやること）

1. 材料を集めて、スクラッチパッドに HTML を書く（`font-family: "IPAGothic", sans-serif` を指定）。
2. 次のコマンドで PDF にする。

   ```bash
   node tools/html-to-pdf.js <入力.html> <出力.pdf>
   ```

3. `pdftotext` で中身を読み直し、金額（「円」「万」「億」を含む数字）とお客様の名前が入っていないか確認する。
   入っていたら直してから作り直す。
4. Gmail の送信で PDF を添付して送る。ドライブの保管フォルダにも同じ PDF を置く。
5. Slack の「事務パイプライン」チャンネルに、メール本文と同じ要点＋PDF の保管場所を投稿する。

## うまくいかなかったとき

- メールが送れない／ドライブに置けない／Slack に投稿できないときは、できた分だけ出し、
  できなかったことと理由を代表あてに知らせる（別の経路に勝手に流さない）。
- 材料が全く読めないときは送らずに止まり、理由を報告する。
