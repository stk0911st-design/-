# 査定未返答アラート（3営業日超過）

業者から物件紹介メールが届いてから **3営業日以内に査定を返していないもの** を検出し、
代表宛にアラートメールを送るルーティンです。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 0 * * *` |
| 日本時間 | 毎日 9:00 |
| 会社休日 | 水曜・日曜（プロンプト側でスキップ。営業日の計算からも除外） |
| 起点 | **業者から物件紹介メールが届いた日**（Backlog の起票日ではない） |
| 起動モード | 既存セッションを継続（Gmail のコネクタを保持しているため） |
| 宛先 | 小林（設定値として管理） |
| 送信条件 | アラート対象が1件以上のときのみ。0件なら送らない |

## なぜ起点を「メール受信日」にしたか

Backlog の起票日を起点にすると、**起票そのものが遅れているケースを見逃します**。
業者から見れば「メールを送ってから何日返事がないか」が全てなので、受信日を起点にしています。

これにより、次の2つを区別して検出できます。

- **未起票**：メールは届いているが、Backlog に課題が立っていない（起票漏れ）
- **未返答**：起票はされているが、査定金額が入っていない・メール返信もない

## Backlog の API キーなしで実現している方法

Backlog 本体を読むには API キーが必要ですが、未設定のままでも判定できています。
**Backlog の通知メールが代表アドレスに届いている**ためです。

```
① 業者からの物件紹介メール（Gmail）
      └─ 受信日 ＝ 起点（0日目）
            │
            ▼  3営業日（水・日を除く）
      ┌─────┴─────┐
      │             │
② メール返信      ③ Backlog コメント通知
   （送信履歴）        （本文に金額の記載）
      │             │
      └─────┬─────┘
          どちらも無ければアラート
```

| 判定 | 根拠 |
| --- | --- |
| 返答済み（メール） | 紹介メールのスレッドに自社からの返信がある |
| 返答済み（Backlog） | コメントに金額の記載がある／課題の状態が処理済み・完了 |
| **アラート対象** | 受信から3営業日超過、かつ上記のどちらも確認できない |
| 未起票 | メールは届いているが、Backlog の起票通知が見当たらない |
| 要確認 | 判断がつかないもの。断定せず別表に載せる |

## 対象とするメール

| | |
| --- | --- |
| 対象 | 業者から自社・社員宛に、具体的な物件を名指しで紹介し、査定・買取検討を求めているもの |
| 対象外 | 一斉配信の物件リスト、ポータルの新着通知、「物件をください」型の買取募集、既存案件の進捗報告・資料送付 |

※ 日次件数レポートでは既存案件の個別連絡も「個別紹介」に数えていますが、
こちらは**新規の査定依頼**だけを対象にしています。目的が違うためです。

**限界**：Backlog 本体を見ていないため、通知メールが届かない操作（メール通知オフの
プロジェクト、通知対象外のユーザーによる更新など）は捕捉できません。
API キーを設定すれば、この方式に頼らず正確に判定できるようになります。

## メールの中身

- 対象一覧：受信日 / 経過営業日数 / 紹介元（業者・担当者）/ 物件名または所在地 / 価格・目線 / 状況
- 5営業日を超えているものは行の背景を赤系にして強調
- 判断がつかなかったものは「要確認」として別表
- 末尾に、通知メール経由の自動判定である旨の注記

## 決めごと

- 判定の根拠が確認できないものを「未対応」と決めつけない
- Backlog へのコメント投稿・課題の更新は行わない（読み取りと報告のみ）
- 送信先は1件のみ
