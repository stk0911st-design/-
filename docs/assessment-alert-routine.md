# 査定未返答アラート（3営業日超過）

物件情報を入手してから **3営業日以内に査定を返していないもの** を検出し、
代表宛にアラートメールを送るルーティンです。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 0 * * *` |
| 日本時間 | 毎日 9:00 |
| 会社休日 | 水曜・日曜（プロンプト側でスキップ） |
| 起動モード | 既存セッションを継続（Gmail のコネクタを保持しているため） |
| 宛先 | 小林（設定値として管理） |
| 送信条件 | アラート対象が1件以上のときのみ。0件なら送らない |

## Backlog の API キーなしで実現している方法

Backlog 本体を読むには API キーが必要ですが、未設定のままでも判定できています。
**Backlog の通知メールが代表アドレスに届いている**ためです。

```
Backlog 通知メール（Gmail）
      │
      ├─「新しい課題を追加しました」 → 物件情報の入手日（起票日）
      │
      └─「新しいコメントを登録しました」 → 査定の返答
           └ 本文に金額の記載があれば「査定済み」と判定
```

これに加えて、Gmail の送信履歴から「元の紹介メールに自社から返信したか」も確認します。

| 判定 | 根拠 |
| --- | --- |
| 査定済み | コメントに金額の記載がある／課題の状態が処理済み・完了 |
| 返答済み | 元の紹介メールのスレッドに自社からの返信がある |
| **アラート対象** | 起票から3営業日超過、かつ上記のどちらも確認できない |
| 要確認 | 判断がつかないもの。断定せず別表に載せる |

**限界**：Backlog 本体を見ていないため、通知メールが届かない操作（メール通知オフの
プロジェクト、通知対象外のユーザーによる更新など）は捕捉できません。
API キーを設定すれば、この方式に頼らず正確に判定できるようになります。

## メールの中身

- 対象一覧：課題キー / 起票日 / 経過営業日数 / 物件名または所在地 / 紹介元 / 起票者 / 状況
- 5営業日を超えているものは行の背景を赤系にして強調
- 判断がつかなかったものは「要確認」として別表
- 末尾に、通知メール経由の自動判定である旨の注記

## 決めごと

- 判定の根拠が確認できないものを「未対応」と決めつけない
- Backlog へのコメント投稿・課題の更新は行わない（読み取りと報告のみ）
- 送信先は1件のみ
