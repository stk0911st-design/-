# 社会人基礎トレーニング（毎朝 Slack＋メール配信）

毎朝、社会人としての基礎知識を「問題＋答え」のセットで5本、Slackとメールに自動配信します。
その場で読んですぐ分かる長さにするのが方針です。

## 配信仕様

| 項目 | 内容 |
| --- | --- |
| 配信曜日 | 月・火・木・金（水曜は休み） |
| 配信時刻 | 8:57（JST） |
| cron（UTC） | `57 23 * * 0,1,3,4` |
| 配信先 | Slack の社内チャンネル1つ ＋ 社内メンバー全員へのメール（BCC）。宛先リストは実行環境側で管理 |
| 集計メール | 前回分の既読状況は、代表宛の別メールにのみ送る（未読者名を全員に出さない） |
| 形式 | 問題(❓)→答え(✅)→ひとこと(💡) を1本ずつ、計5本 |
| 既読確認 | Slack投稿への ✅ リアクションを「読んだボタン」として使い、次回配信時に集計 |
| 実行方式 | Claude のルーティン（既存セッションを継続。Slackコネクタを保持しているため） |

JST 8:57 は UTC 23:57 で日付が前日に戻るため、曜日指定も1日ずらして
`0,1,3,4`（日・月・水・木）になります。

## 5本の構成

| 枠 | テーマ | 例 |
| --- | --- | --- |
| 1本目 | 社会人マナー（中級編） | 上司を飛ばして報告したときの立て直し、指示の食い違い、リスケの申し出、断り方、ミス報告 |
| 2本目 | ビジネスメール（中級編） | 催促の段階、こじれた案件のお詫び、日程再調整、断りのメール、代筆・代理送信、CC/BCCの巻き込み方 |
| 3本目 | 日替わりローテーション（中級編。下記3ジャンルを順番に） | ― |
| 4本目 | 不動産豆知識（初級編） | 坪と㎡、建ぺい率と容積率、接道義務、媒介契約の違い、重要事項説明、登記簿の甲区乙区 |
| 5本目 | 広告・販促のルール（固定枠） | 社外に出す広告物は必ず社内の許可を取ってから |

①②③は「中級編」＝新人向けの基本ではなく、実務で判断に迷う場面を扱います。
④の不動産豆知識は「初級編」で、基本用語を1回に1つずつ確実に覚える枠です。
⑤は毎回の固定枠で、社外に出す広告物の社内承認ルールを繰り返し伝えます。

3本目のローテーション：

1. 一般社会常識・ビジネスマナー（席次の応用＝タクシー・エレベーター・和室、訪問先での振る舞い、会食の段取り、手土産）
2. 電話応対・緊急時の連絡（クレームの一次対応と引き継ぎ、言いにくい伝言、折り返しの管理、緊急連絡の第一報）
3. 冠婚葬祭・お悔やみ対応（訃報の社内展開、弔電・供花の手配、お悔やみメールの文面、慶弔金と表書き）

配信のたびに 1→2→3→1… と順に進めます。
前回どこまで進んだかは、配信先チャンネルの直近の投稿（見出しに `【社会人基礎トレーニング】` が入っている）
を読んで判断します。判断できない場合は「1. 一般社会常識」から始めます。

### 4本目「不動産豆知識（初級編）」の方針

- 新人でも分かる基本用語・基礎知識を1回につき1つだけ扱う
- 専門用語はやさしい言葉に開いて説明する
- 数字は正確に。あいまいなものは扱わない
- 法令・税制の細かい要件には踏み込まず、用語を確実に覚えられる形にする
- 自社の実案件は題材にせず、一般的な事例で書く

### 5本目「広告・販促のルール」の方針

毎回かならず次の一点を本文に入れます。

> 社外に出す広告物は、必ず社内の許可を取ってから。
> チラシ、DM、ポスティング、ネット広告（ポータルサイト、SNS、リスティング、自社サイトの掲載内容）まで、
> 社外の目に触れるものはすべて対象。個人の判断で出さない——これは社会のルールです。

この一点を軸に、切り口だけを毎回変えます（自作チラシ、SNSでの物件紹介、ポータル掲載内容の変更、
写真・間取り図の使用、他社チラシの流用、「日本一」「最安」などの表現、おとり広告の禁止、
取引態様や免許番号の明示、価格・面積の表示、DM宛先リストの扱い など）。

背景として、不動産広告には表示のルール（景品表示法、不動産の表示に関する公正競争規約）があり、
違反すると会社の責任になる点にやさしく触れます。細かい条文には踏み込みません。
注意・叱責ではなく「先に一声かければ安心して出せます」という前向きな伝え方にします。

## 読んだボタン（既読の確認）

Slackの投稿に押す **✅ リアクション** を「読んだボタン」として使います。
Slack標準の機能なので、メンバー側の準備は不要です。

- 投稿の末尾に「読み終えたら ✅ を押してください」と入れる
- 投稿直後に自分で ✅ を1つ付けておき、押しやすくする
- メール版には、そのSlack投稿へ飛ぶボタン風リンクを置く

### 集計の仕方

次の配信のときに、前回の投稿のリアクションを読んで集計します。

1. 前回の「社会人基礎トレーニング」投稿の ✅ を押した人を「読んだ人」とする
2. チャンネルのメンバー一覧（bot・削除済みを除く）と突き合わせ、押していない人を出す
3. 結果は **代表宛の集計メールにだけ** 記載する
   （未読者名はチャンネルにも全員宛メールにも出さない）
4. 金曜の配信では、その週の平均既読率と皆勤者もあわせて報告する
5. 人数と既読率は `docs/read-log.md` に1行追記して記録に残す（氏名は残さない）

### 本物のボタンにしたい場合

Slackで「ボタンを押す」UIを出すには、Interactivity（対話性）を有効にした
Slackアプリと、押下を受け取るサーバー（Google Apps Scriptなど）が必要です。
現在の ✅ リアクション方式は、その準備なしで同じことができる代替です。

## 重複を避ける仕組み

実行時に配信先チャンネルの直近の投稿を読み、すでに出題済みのテーマと
重複しない問題を作ります。過去ログはチャンネルそのものを台帳として使います。

## 敬称・呼び方のルール（2本目でよく出る論点）

- 社内の上司を社内向けに書くとき：役職は敬称なので「高橋課長」。「高橋課長様」は二重敬語で誤り。
- 社外に自社の上司を出すとき：敬称・役職の「様」を付けず「課長の高橋」または「高橋」。
- 社外の相手：「株式会社○○ 営業部 部長 ○○様」のように、会社名→部署→役職→氏名＋様。

## 文章のトーン

朝いちばんに読むものなので、明るく・やさしく・短くを優先します。

- 「できていないと恥ずかしい」ではなく「知っていれば安心」「これだけ押さえればOK」
- 中級編でも難しく書かない。判断に迷う場面を、その場で使える形で示す
- 命令口調（〜しなさい／〜すべき）は使わない。「〜すると安心です」「〜が伝わります」
- 1文を短く。答えは3〜4行以内
- そのまま口に出せる・コピペできるセリフを「」で1つ入れる
- 絵文字は ❓（問題）✅（答え）💡（ひとこと）の決まった位置だけ
- 最後にその日の内容に合った短い応援の一言を添える（毎回同じ文言にしない）

## ルーティンのプロンプト

社内情報（チャンネルID）は伏せています。実際のルーティンには実値を入れて登録してください。

```text
【定期実行】社会人基礎トレーニングのSlack配信です。以下の手順どおりに実行してください。

1. 今日の日付・曜日（JST）を確認する。月・火・木・金のみ配信。それ以外の曜日なら何もせず終了する。
2. Slack の slack_read_channel でチャンネル <CHANNEL_ID> の直近30件を読み、
   見出しに「【社会人基礎トレーニング】」が入った過去の投稿を確認する。
   - 3本目のジャンルが前回どれだったかを見て、今回は次のジャンルにする
     （1.一般社会常識・ビジネスマナー → 2.電話応対・緊急時の連絡 → 3.冠婚葬祭・お悔やみ対応 → 1に戻る）。
     判断できなければ 1 から始める。
   - 過去に出題済みの問題とテーマが重複しないようにする。
3. 問題を5本つくる。①②③は【中級編】（実務で判断に迷う場面）、④は【初級編】、⑤は固定枠。
   ①社会人マナー（中級編）、②ビジネスメール（中級編）、
   ③手順2で決めたローテーションのジャンル（中級編）、④不動産豆知識（初級編：基本用語を1つ）、
   ⑤広告・販促のルール（社外に出す広告物は必ず社内の許可を取ってから）。
   敬称ルール：社内向けは「高橋課長」（「高橋課長様」は誤り）、社外向けは「課長の高橋」。

   ■ 文章のトーン（重要）
   - 明るく、やさしく、読みやすく。朝いちばんに読んで気持ちが軽くなる感じ。
   - 「できていないと恥ずかしい」ではなく「知っていれば安心」という書き方。
   - 命令口調は使わない。「〜すると安心です」「〜が伝わります」とやわらかく。
   - 中級編でも難しく書かない。「知っていれば安心」「こう返せば大丈夫」という書き方。
   - 1文を短く。答えは3〜4行以内。5本あるので全体が長くなりすぎないように。
   - ⑤も注意・叱責ではなく「先に一声かければ安心して出せます」という前向きな伝え方にする。
   - そのまま口に出せる・コピペできるセリフや文例を「」で1つ入れる。
   - 絵文字は各ブロックの決まった位置だけ（❓ ✅ 💡）。

4. slack_send_message でチャンネル <CHANNEL_ID> に1通だけ投稿する。書式：

   ☀️ **【社会人基礎トレーニング】YYYY年M月D日(曜)**
   おはようございます。今日の5本です。1〜2分でお読みいただけます。

   **① 社会人マナー（中級編）：<小見出し>**
   ❓ <場面の問題。1〜2行>
   ✅ <答え。3〜4行以内。「」でそのまま使えるひとことを入れる>
   💡 <やさしい補足を1行>

   **② ビジネスメール（中級編）：<小見出し>**
   ❓ ... / ✅ ... / 💡 ...

   **③ <ジャンル名>（中級編）：<小見出し>**
   ❓ ... / ✅ ... / 💡 ...

   **④ 不動産豆知識（初級編）：<用語や小見出し>**
   ❓ ... / ✅ ... / 💡 ...

   **⑤ 広告・販促のルール：<小見出し>**
   ❓ ... / ✅ ... / 💡 ...

   （最後に、その日の内容に合った短い応援のひとことを1行だけ添える。毎回同じ文言にしない）

5. 続けて Gmail の send_message で、同じ5本を社内メンバー全員に送る
   （to は代表1件、残りは bcc。宛先リストは実行環境側で管理）。
   件名は「【社会人基礎トレーニング】YYYY年M月D日(曜)」。htmlBody で、
   上部に薄いオレンジの見出しブロックとSlack投稿へのボタン風リンク、
   5本それぞれを左に色付きの縦線を引いたブロックにして ❓ ✅ 💡 の3行で構成する。
   このメールには既読集計・未読者名を入れない。body にはプレーンテキスト版も入れる。
5-2. 続けて、代表宛（1件のみ）に「【既読集計】…」の別メールを送る。
   前回の配信日、既読 n/m 名（既読率）、未読の方の氏名、今日のSlack投稿リンク。
   金曜はその週の平均既読率と皆勤者も添える。
6. Slack・メールとも1日1通のみ。すでに同じ日付の投稿がチャンネルにあれば二重送信せず終了する。
7. 送信後、5本の小見出し・3本目のジャンル・Slack投稿リンク・メール送信の可否を報告して終了する。

このチャンネルは社内向け。指定のチャンネル以外に投稿したり、社外へ送ったりしないこと。
特定の個人・取引先を題材にせず、一般的な事例として書くこと。
誰かを注意する・叱るような書き方はしないこと。
```

## 運用メモ

- 祝日は考慮していません。祝日も配信されます。止めたい場合はルーティンを一時停止してください。
- 配信先を自分宛DMや別チャンネルに変えたい場合は、ルーティンのプロンプト内のチャンネルIDを変更します。
- メール配信をやめる場合は、ルーティンのプロンプトから手順5を削除します。
- 曜日・時刻の変更はルーティンの cron（UTC）を変更します。
