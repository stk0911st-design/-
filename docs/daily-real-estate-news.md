# 不動産ニュース記事 毎朝配信ルーティン

毎朝 8:00（JST）に日本の不動産ニュースを調査し、記事・note原稿・X用要約を作成して
Slackへ投稿、原稿をGoogleドライブへ保存、実行ログをメールで残す自動化です。

## 仕様

| 項目 | 内容 |
| --- | --- |
| 実行タイミング | 毎日 8:05（JST）※cron は UTC で `5 23 * * *` |
| 起動モード | 既存セッションを継続（コネクタを保持しているため） |
| 調査範囲 | 日本の不動産ニュース。東京23区を最優先 |
| 必須トピック | 金利／融資／不動産価格／買取再販市場 |
| 記事の長さ | 1,500〜2,500文字（記号・空白を除く本文） |
| 成果物 | ①note掲載用の記事原稿 ②X用の280文字以内の要約 |
| 配信先 | Slack の社内チャンネル（人がXへ手動投稿） |
| 投稿時刻 | 日本時間 7:00〜10:00 のみ。それ以外の時刻に実行した場合は次の朝8:10へ予約投稿 |
| 原稿の保存先 | Googleドライブのフォルダ「不動産ニュース記事」 |
| ログの保存先 | Gmail（件名 `【不動産ニュース投稿ログ】YYYY-MM-DD`）→ GASでスプレッドシートへ転記 |

## この環境でできること・できないこと

ルーティンを設計するうえで実測した制約です。

| やりたいこと | 可否 | 備考 |
| --- | --- | --- |
| Web検索でニュースを調べる | ○ | `WebSearch` は利用可 |
| 記事URLを直接開いて読む | ✕ | `WebFetch` は egress プロキシに遮断される。検索結果の要約で裏取りする |
| Xへ自動投稿 | ✕ | X／Twitter のコネクタが存在しない。原稿をSlackに出し、人が投稿する |
| noteへ自動投稿 | ✕ | 同上。原稿をドライブに保存し、人が貼り付ける |
| Googleドライブにファイルを新規作成 | ○ | `create_file` |
| 既存スプレッドシートに行を追記 | ✕ | Driveコネクタの `update_file` はタイトルと保存場所の変更のみ |
| Slackリストに行を追加 | ✕ | `bot_not_found`。アプリに書き込み権限がない |
| Slackにメッセージ投稿 | ○ | `slack_send_message` |
| Gmail送信 | ○ | `send_message` |
| 新規セッション起動型のルーティンでコネクタを使う | ✕ | 新規セッションにはコネクタが引き継がれない。既存セッションを起こす方式にする必要がある |

このため「毎日1行ずつ増えるログ」は、Claudeが**メールで送り**、
GAS（`gas/NewsPostLogger.gs`）が**スプレッドシートへ転記する**二段構えにしています。

## 事実確認のルール

`WebFetch` が使えないため、記事に書く数値は次の条件を満たすものだけを使います。

1. 複数の検索結果で同じ数値が確認できること。
2. 出典（調査機関名・報道機関名）と時点（何年何月のデータか）を本文に明記できること。
3. 将来の価格・金利を断定しないこと。「必ず」「絶対」「今が買い時」といった誇張表現を使わない。
4. 金利は「各行が公表する最優遇適用金利であり、実際の適用金利は審査により異なる」旨の注記を必ず入れる。
5. 半年以上前のデータを最新として扱わない。古い数値しか取れない場合は、その時点を明記する。

裏取りができない数値は、記事に書かずに落とします。

## ルーティンのプロンプト

社内情報（SlackチャンネルID・ドライブのフォルダID・宛先アドレス）は伏せています。
実際のルーティンには実値が入っています。

```text
【定期実行】毎朝の不動産ニュース記事です。以下を順に実行してください。

1. WebSearch で日本の不動産ニュースを調べる。東京23区を最優先。
   次の4つは毎回必ず調べる：金利（日銀の政策金利・住宅ローン金利）／融資（審査・借入可能額）
   ／不動産価格（レインズ等の成約データ、23区の中古マンション・戸建て）／買取再販市場。
   WebFetch はこの環境では遮断されているため使わない。検索は複数クエリで行い、
   同じ数値が複数の結果で確認できるものだけを採用する。

2. 調べた中から、スマートハウスのお客様（23区で家を売る人・買う人・すでに住宅ローンを
   借りている人）にとって実務的に役立つテーマを1つだけ選ぶ。総花的なまとめにしない。

3. そのテーマで記事を書く。本文1,500〜2,500文字（記号・空白を除く）。
   構成は「何が起きたか（事実と数値）→ それが家計や取引にどう効くか → 読者が今やること」。
   数値には必ず出典と時点を添える。断定的な将来予測、誇張表現、煽り表現は使わない。
   末尾に「※金利は各行公表の最優遇適用金利であり、実際の適用金利は審査により異なります。
   市場データは各調査機関の公表値であり、将来の価格や金利を保証するものではありません。」を入れる。
   参照ソースの一覧も末尾に付ける。

4. 公開前チェックを行う。①誇張表現がないか ②数値と出典が一致しているか
   ③半年以上前のデータを最新として扱っていないか ④文字数が範囲内か。
   問題があれば直してから次へ進む。

5. X用に280文字以内の要約を作る。必ず文字数を数えて確認する。
   ハッシュタグを含めて280文字以内に収める。URLは入れない。

6. note用原稿を Googleドライブに保存する。create_file で
   parentId `<DRIVE_FOLDER_ID>`（フォルダ「不動産ニュース記事」）、
   contentMimeType `text/markdown`、
   タイトル `不動産ニュース記事_YYYY-MM-DD_<テーマの短い要約>`。
   本文に Markdown の表は使わない。Googleドキュメントへの変換で見出し行が空になり、
   セル内の `**` が文字として残るため。表にしたい内容は箇条書きで書く。

7. Slack の `<SLACK_CHANNEL_ID>` に投稿する。内容は
   ・見出し「【本日の不動産ニュース記事】YYYY年M月D日」
   ・X投稿用の原稿（280文字以内、そのままコピーして投稿できる形で）と文字数
   ・記事の要点3行
   ・note原稿のドライブURL
   ・参照ソース
   Xとnoteへの投稿は人が手動で行う旨を1行添える。

   投稿時刻の制約：Slackへの投稿は日本時間の朝（7:00〜10:00）だけに行う。
   まず `TZ=Asia/Tokyo date` で現在時刻を確認し、その範囲内なら slack_send_message で即時投稿する。
   範囲外（昼・夕方・夜間・深夜）なら slack_send_message は使わず、slack_schedule_message で
   「次に来る朝8:10（JST）」に予約投稿する。深夜・夜間にチャンネルへ流さないこと。

8. 実行ログをメールで残す（時刻の制約を受けない。自分宛のため）。send_message で宛先 `<LOG_MAIL_TO>`、
   件名 `【不動産ニュース投稿ログ】YYYY-MM-DD`、本文はプレーンテキストで
   次の形式（GASがこの形式を解析してスプレッドシートに転記する）。

   日付: YYYY-MM-DD
   テーマ: ...
   記事タイトル: ...
   文字数: 1983
   note原稿URL: https://docs.google.com/document/d/.../edit
   X要約: ...
   X投稿URL: 未投稿
   参照ソース: 出典1、出典2、出典3
   Slack投稿URL: https://...

9. 調査で有用なニュースが見つからなかった場合は、記事を無理に書かない。
   Slackにその旨だけを1行投稿し、ログメールにも「該当なし」と記録して終了する。

社内の物件情報・顧客情報・売上などの非公開情報は、記事にも投稿文にも一切含めないこと。
記事の内容は公開情報のみで構成する。
```

## GAS側（スプレッドシートへの転記）

`gas/NewsPostLogger.gs` を Apps Script に貼り付け、時間主導トリガーで毎朝9:00に実行します。
ログメールを読み取り、スプレッドシートへ1行ずつ追記します。導入手順は `gas/README.md` を参照。

## 運用メモ

- Xとnoteへの投稿は人の手作業です。投稿後、スプレッドシートの「X投稿URL」列に
  URLを貼っておくと、あとから効果を振り返れます。
- 記事のテーマが数日続けて似てきた場合は、直近のログを見て別の切り口を選ばせます。
- note原稿に Markdown の表を書くと、Googleドキュメントへの変換で崩れます
  （見出し行が空行になり、セル内の `**` がそのまま残る）。数値の比較は箇条書きにします。
- Slackへの投稿は朝の時間帯（7:00〜10:00 JST）に限定しています。手動で走らせたときや
  ルーティンが遅延したときに、夜間のチャンネルへ流れないようにするためです。
  範囲外の時刻に実行した場合は、次の朝8:10へ予約投稿されます。
  予約時刻の計算は「tomorrow 08:10」だけを使うと深夜0時台に1日ずれるため、
  `today 08:10` が過去なら `tomorrow 08:10` を使う、という形で求めます。
- ルーティンは日本時間8:05に起動します（他のルーティンが8:00に集中しているため5分ずらしています）。
- ルーティンは「既存セッションを継続」する方式です。新規セッション起動型にすると
  Googleドライブ・Slack・Gmail のコネクタが引き継がれず、手順6〜8が実行できません。
  営業日報のルーティンと同じ構成です。
