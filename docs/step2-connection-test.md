# ステップ② 疎通テスト（所要 5分ほど）

入力アプリの画面から、受け皿へ通信できるかどうかを確かめます。
**ここが今回いちばんの分かれ道**です。通れば完全自動化、通らなければ別の方法に切り替えます。

## やること

日報カウンターのコードの、いちばん最後（`</script>` の直前）に次を貼り付けて、再公開します。

```js
/* ===== 疎通テスト用。確認が終わったら消してください ===== */
const SYNC_URL   = "ここにウェブアプリのURLを貼る";
const SYNC_TOKEN = "ここに合言葉を貼る";
(function pingSync(){
  try{
    fetch(SYNC_URL, {
      method: "POST",
      mode: "no-cors",
      headers: {"Content-Type": "text/plain;charset=utf-8"},
      body: JSON.stringify({
        token: SYNC_TOKEN,
        type: "ping",
        from: "nippo",
        note: "疎通テスト " + new Date().toISOString()
      })
    });
  }catch(e){ /* 届かなくても画面は止めない */ }
})();
```

`Content-Type` を `text/plain` にしているのは、ブラウザの事前確認（プリフライト）を
避けるためです。`mode:"no-cors"` なので**返事は読めません**。届いたかどうかは
スプレッドシート側で確認します。

## 確認のしかた

1. 貼り付けて再公開する
2. 公開された URL（`claude.site` で始まるもの）をブラウザで開く
3. 受け皿のスプレッドシートの **`_log` タブ**を見る

| `_log` に行が増えた | 判定 |
| --- | --- |
| 増えた | **通信できます。** ステップ③（本番の同期）に進めます |
| 増えない | 通信が塞がれています。別方式に切り替えます |

※ プレビュー画面ではなく、**公開された claude.site の URL** で開いてください。
プレビューでは保存も通信も動きません。

## 増えなかった場合の代替案

1. **半自動**：画面に「今日のぶんを送る」ボタンを置き、1日1回押してもらう
   （それでも通信が要るので、通信自体が塞がれている場合は不可）
2. **書き出し経由**：アプリの「バックアップ（JSON）」を Google ドライブの決まった
   フォルダに保存してもらい、そのファイルを読んで集計する
3. **入力アプリの作り直し**：保存先を最初から読み取り可能な形にする
