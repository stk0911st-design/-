# RS先 物件紹介台帳

RS（レベニューシェア）先・出口先ごとに、**相手が欲しい物件の条件**と、
**こちらが紹介した／これから紹介する物件**を1行で見るための台帳です。
`web/rs-ledger.html` を Claude のアーティファクトとして公開して使います。

## 画面の構成

| 列 | 内容 |
| --- | --- |
| 先・担当・進捗 | 業者名／担当者／区分／資金枠／関係の状況／進捗ステップ |
| 相手が欲しい物件 | エリア・種別・価格帯・権利・引渡し・備考（未入力なら「未ヒアリング」表示） |
| 紹介した物件／紹介予定 | 1件ずつ登録。状態を5段階で色分け |
| 次の一手 | 次にやること＋期限（超過すると赤くなり、行の左に帯が出る） |

進捗ステップは入力内容から自動判定します（条件把握 → 候補選定 → 提示 → 反応）。

物件の状態は5つです。

| 状態 | 意味 |
| --- | --- |
| 紹介予定 | これから出す候補。まだ相手に見せていない |
| 返答待ち | 提示済で回答待ち |
| 前向き | 条件交渉中 |
| 成約 | 決まった |
| 見送り | 断られた（理由はメモに残す） |

## データの保存先

アーティファクトの `db` 機能（`partners` コレクション、1社＝1ドキュメント）に保存します。
入力は自動保存され、別の端末で開いても同じ内容が見えます。
`db` が使えない環境ではブラウザのローカル保存に切り替わり、画面右上に「この端末に保存（同期なし）」と出ます。

ドキュメントの構造:

```
co      業者名          who   担当者
cat     区分 rs / exit / src  status 関係の状況
money   資金枠          want  {area,type,price,rights,cond,memo} 相手の希望条件
hist    [{date,name,area,type,price,state,memo}] 紹介した物件・紹介予定
next    次の一手        due   期限（YYYY-MM-DD）
order   並び順
```

`state` は `plan`（紹介予定）/ `wait`（返答待ち）/ `good`（前向き）/ `deal`（成約）/ `ng`（見送り）。

※ 業者名・担当者などの取引先情報はこのリポジトリには置きません。
アーティファクトのデータベース側にだけ保存します。

## 朝メール（毎日9時）

Claude のルーティンで毎朝 9:03（JST）に台帳を読み、その日の動きをメールします。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `3 0 * * *` |
| 対応する日本時間 | 毎日 9:03 |
| 宛先 | 本人のアドレス1件（設定値として管理） |
| 起動モード | 既存セッションを継続（Gmailコネクタを保持しているため） |

メールの中身:

1. 件数サマリ（社数・紹介予定・返答待ち・前向き成約・条件未ヒアリング）
2. 今日やること（期限が今日以前の先。超過日数つき）
3. 返答待ち（物件名・提示日・経過日数）
4. 紹介予定（相手の希望条件と並べて表示）
5. 動きが止まっている先（紹介0件／条件未ヒアリング）
6. 前向き・成約の状況

台帳が読めなかった場合はメールを送らず、原因を報告して終了します。
