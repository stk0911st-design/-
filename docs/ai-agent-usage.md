# Claude Code と Codex を併用する

このリポジトリは、Claude Code と Codex のどちらで開いても同じルールで作業できます。
ルールの実体は `AGENTS.md` の1つだけで、Claude Code は `CLAUDE.md` 経由でそれを読みます。

## Codex ではじめて開くとき

1. お使いのPCに、このリポジトリを取ってくる（すでにあるなら最新にする）

   ```sh
   git clone https://github.com/stk0911st-design/-.git
   cd -
   git pull
   ```

2. そのフォルダで Codex を起動する

   ```sh
   codex
   ```

   （Codex CLI が未導入なら `npm install -g @openai/codex` などで先に入れます）

3. 起動したフォルダに `AGENTS.md` があれば、Codex は自動で読みます。
   設定作業は要りません。「AGENTS.md を読んで」と言う必要もありません。

Claude Code 側も同じで、同じフォルダで `claude` を起動するだけです。

## 使い分けの目安

決まりではなく目安です。どちらか片方だけでも問題ありません。

| 場面 | 向いているほう |
| --- | --- |
| 何をどう直すか相談しながら進める | Claude Code |
| Google ドライブ・Gmail など外部サービスを触る | Claude Code（コネクタを持っているため） |
| 決まった修正を手早く回す | Codex |
| 同じ問題を別の視点で見てほしい | もう片方に同じことを聞く |

## 併用するときの注意

**いちばん起きやすい事故は、同じファイルを両方で同時に直すことです。**
AI どうしは互いの作業を知らないので、あとから push したほうが弾かれるか、
`git pull` したときに衝突（コンフリクト）になります。

避け方は次の3つです。

1. **同時に走らせない。** 片方の作業が終わってコミットしてから、もう片方を動かす。
2. **触る範囲を分ける。** どうしても同時に動かすなら、`gas/` は片方、`docs/` はもう片方、
   のようにフォルダ単位で担当を分ける。
3. **始める前に必ず最新にする。** 作業開始時に `git pull`、終わったらすぐコミットして push。

衝突が起きてしまった場合は、自分で直そうとせず、どちらかのAIに
「コンフリクトが出た」とそのまま伝えれば解消できます。

## 変更するときの決まり

- 作業ルールを変えたいときは **`AGENTS.md` だけ**を直す（`CLAUDE.md` は触らない）
- 社内情報（スプレッドシートID・メールアドレス・個人名・合言葉）はコミットしない
- 詳しくは `AGENTS.md` を参照
