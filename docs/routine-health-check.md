# ルーティン点検手順（メール未送信の防止）

2026-09-24 の点検で、「実行済み（SUCCEEDED）」と表示されているのに
実際にはメールが1通も出ていないルーティンが複数見つかった。
その原因と、ルーティンを作る・点検するときの確認項目をまとめる。

※ 宛先・スプレッドシートID などの社内情報はここに書かない（`CLAUDE.md` 参照）。

## 見つかった原因

| 原因 | 症状 | 対処 |
| --- | --- | --- |
| 毎回新しい会話で起動する型なのに、コネクタ（Gmail 等）を付けずに登録した | 調査は動くが送信できずに終わる。実行ログ上は正常終了 | コネクタ付きで作り直す（コネクタは後から追加できないため、作り直し→旧版は停止） |
| 既存の会話につなぐ型で、その会話から Gmail・Slack が外れた | 起動後 10〜30 秒で終わる | 新しい会話で起動する型＋コネクタ付きに切り替える |
| 許可モードが自動になっていない | 「操作の許可待ち」で止まり、誰も気づかない | 自動許可の付いた状態で登録し直す |
| 返信の差出人を1つのアドレスに限定していた | 相手が別アドレス（個人 Gmail 等）から返信すると検知できない | 差出人ではなくスレッド（件名）で返信を判定する |

## 注意：「SUCCEEDED」は送信成功の意味ではない

`list_triggers` の `last_run.status` は、既存の会話につなぐ型では
「起動メッセージを届けた」ことしか表さない。メールが出たかどうかは
**Gmail の送信済みフォルダで件名を検索して確かめる**。

## ルーティンを登録するときの確認項目

1. 起動の型：毎回新しい会話で起動する型を基本にする。
2. コネクタ：メールを送るなら `Gmail` を必ず付ける。
   Slack・ドライブ・カレンダーを読むならそれも付ける。
3. プロンプトの冒頭で、使うツールを ToolSearch で読み込ませる。
   見つからないときは黙って終わらず、最終報告の1行目に「未接続のため送信できず」と書かせる。
4. 登録直後に1回だけ手動実行（fire）し、送信済みフォルダに届いたことを確認する。
5. 次の定時実行のあとにも、送信済みフォルダで件名を確認する。

## 定期点検（送信監視）

毎日 昼・夜 の2回、次を行う監視ルーティンを置く。

1. 有効なルーティン一覧を取得する。
2. その時刻までに送られているはずの件名を、Gmail の送信済み（当日分）で検索する。
3. 見つからないもの・実行が止まっているもの（許可待ち等）があれば、
   代表の登録アドレスすべてに警告メールを送る。
