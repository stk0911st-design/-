# 東京23区 中古マンション「売出件数・成約件数」日次トラッカー 実現可能性調査

調査日: 2026-09-04

## 1. 結論（先に要点）

| ご要望 | 可否 | 理由 |
| --- | --- | --- |
| 毎日18:00にメール送信 | **可能** | 既存の GAS + Gmail 構成をそのまま流用できる |
| 数値をDB（スプレッドシート）に毎日蓄積 | **可能** | 同上 |
| 23区**合計**の売出件数 | **条件付きで可能** | 公式は月次・「東京都区部」単位。日次は無料の合法ソースが存在しない |
| **区別**の売出件数 | **公式ソースなし** | 区別×日次を公開している無料データは見つからず。ポータル取得は規約・robots.txt でNG |
| 23区**合計**の成約件数 | **月次なら可能** | レインズ月例速報（都区部単位・月1回・翌月中旬公表） |
| **区別**の成約件数 | **日次は不可能** | 区別は年報／四半期レベル。日次の成約数はレインズ会員向けにも公表されていない |

**要するに:** 「毎日18時にメールを送って蓄積する」仕組み自体は問題なく作れます。
ただし **中身のデータが毎日は更新されません。** 成約件数は世の中に日次データが存在せず、
売出件数の区別日次データも、無料かつ規約上クリーンな取得先がありません。

## 2. 検証したデータソース

### 2-1. レインズ（東日本不動産流通機構）月例速報 Market Watch
- URL: https://www.reins.or.jp/library/ / PDF例: `https://www.reins.or.jp/pdf/trend/mw/mw_YYYYMM_summary.pdf`
- 内容: 中古マンションの **成約件数 / 新規登録件数 / 在庫件数 / 成約価格**
- 地域粒度: 首都圏 → 都県別 → 地区別（**東京都区部**／多摩／横浜川崎 など）。**23区の区別は無し**
- 更新頻度: **月1回**（前月分を翌月中旬に公表）。季報・年報あり
- 費用: 無料・PDF（＋一部Excel）
- 評価: **成約件数の唯一の公的ソース。ただし月次・都区部まとめ。**

### 2-2. 不動産情報ライブラリ API（国土交通省）
- URL: https://www.reinfolib.mlit.go.jp/help/apiManual/
- API: XIT001（不動産価格・取引価格/成約価格情報取得）、XIT002（都道府県内市区町村一覧）
- 地域粒度: **市区町村コード単位＝23区の区別が取れる**
- 更新頻度: **四半期ごと**（公表は取引の約3〜6か月後）
- 費用: 無料。ただし**API利用申請→審査→APIキー発行**が必要
- 注意: これは「**取引実績（成約）**」であって「**売出中の在庫**」ではありません
- 評価: **区別データが合法・無料で取れる唯一のAPI。ただし四半期＆大幅なタイムラグ。**

### 2-3. 不動産ポータル（SUUMO / LIFULL HOME'S / at home）
- 「東京都○○区 × 中古マンション」の検索結果件数＝ほぼリアルタイムの売出件数で、
  日次・区別データとしては理想的
- **ただし取得は不可と判断:**
  - SUUMO 利用規約は商用利用・不正利用を禁止（https://suumo.jp/edit/kiyaku/）
  - SUUMO の robots.txt は **検索結果ページ・物件詳細ページを Disallow** 指定。件数が出るのはまさにこのページ
  - 他ポータルも同様の規約構成
- 評価: **規約・robots.txt 違反となるため、この方式は採用しない。**
  （参考: 本調査環境からは suumo.jp / homes.co.jp / athome.co.jp への接続自体が
   ネットワークポリシーでブロックされており、技術的にも実行不可）

### 2-4. 不動産ジャパン（公益財団法人 不動産流通推進センター）
- URL: https://www.fudousan.or.jp/trend/cyum.html
- レインズ登録物件をベースにした一般公開サイト。相場・取引動向を掲載
- 評価: 参考値としては有用だが、**区別×日次の件数を機械的に提供する形にはなっていない**

### 2-5. 有料データベース事業者
- マンションリサーチ、ワンノブアカインド、コラビット等が不動産データ販売／API提供
- 相場感: **月額10万円〜**（プランにより変動）
- 評価: 日次・区別の在庫データが必要な場合、**唯一の正攻法**。要個別見積り

## 3. 実現可能な3案

### 案A：公的データのみ・完全合法（推奨）
- 毎日18:00にGASが起動
- レインズ月例PDF（月次・都区部）＋ 不動産情報ライブラリAPI（四半期・区別）を巡回
- 新規公表があればスプレッドシートに追記、無ければ前回値を据え置き
- メール本文: 最新値 ／ 前月比・前年同月比 ／ 区別ランキング ／ 次回公表予定日
- **長所:** 規約リスクゼロ・無料・恒久運用可
- **短所:** 数値が動くのは月1回（区別は四半期に1回）

### 案B：案A ＋ 有料DB契約で日次・区別データを追加
- データ提供事業者と契約し、日次の売出在庫を区別で取得
- **長所:** ご要望どおり「毎日動く区別データ」が実現
- **短所:** 月額10万円〜のコスト。契約・与信が必要

### 案C：自社（自分）で扱える物件データを起点にする
- 業務上アクセスできるレインズ等の情報を、手元で日次記録する運用
- **注意:** レインズ画面情報の自動取得・外部保存は会員規程に抵触する恐れあり。要確認

## 4. 推奨構成（案Aの技術設計）

```
Google スプレッドシート「23区マンション指標」
  ├ シート: daily_log     … 実行日 / ソース / 対象期 / 区 / 売出(登録) / 成約 / 在庫
  ├ シート: monthly_reins … レインズ月例（都区部）
  └ シート: quarterly_ward… 不動産情報ライブラリ（区別・四半期）
        ↑
  GAS 時間主導トリガー 毎日 18:00 JST
        ↓
  Gmail で本人宛にHTMLメール送信
```

- 既存の `gas/DailyReportMailer.gs`（毎朝8:00の営業日報メール）と同じ枠組み
- データは**追記のみ・削除なし**（過去値は上書きせず履歴として保持）
- API キー・宛先アドレスは Apps Script のスクリプトプロパティで管理し、リポジトリには置かない

## 5. 確認が必要な事項

1. 案A / 案B / 案C のどれで進めるか
2. 「成約」の定義：レインズ成約件数（月次）か、国交省の取引実績（四半期）か、両方か
3. メール宛先（本人のみか、他にも送るか）
4. 有料DBを検討する場合、予算の上限
