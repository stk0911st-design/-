# 南万騎が原駅 中古マンション 売り出し／成約 事例トラッカー

相鉄いずみ野線 **南万騎が原駅**（横浜市旭区）を最寄りとする中古マンションについて、
週に1回「いま売りに出ている物件」のスナップショットを取り、前週との差分から
**新規掲載 / 価格改定 / 掲載終了** を判定して積み上げていく仕組みです。
成約事例は別ルートで取得し、同じ台帳に並べます。

## なぜスナップショット方式なのか

ポータルサイトの一覧は「今この瞬間に出ている物件」しか見せません。
毎週それを写し取って前週と突き合わせることで、単なる一覧では取れない情報が残ります。

| 差分 | 意味 |
| --- | --- |
| 前週になくて今週ある | 新規売り出し |
| 価格が変わった | 値下げ／値上げ（回数と累計幅を記録） |
| 前週にあって今週ない | 掲載終了（成約 or 取下げ） |
| ずっと出ている | 滞留（掲載週数として蓄積） |

**掲載終了＝成約ではありません。** 売主都合の取下げや媒介先の変更も同じ見え方になります。
成約の確定は、レインズの成約事例または国交省の成約価格情報で照合してください。

## データの置き場所

**台帳の本体は Google ドライブです。リポジトリにはコードだけを置きます。**

レインズ由来の売り出し情報は社外秘であり再配布もできないため、GitHub には一切コミットしません
（`data/` と `reports/` は `.gitignore` 済み）。

Google ドライブ フォルダ「南万騎が原 マンション台帳」
（`16kPnXF8IYWuKe1_KTuFNbFUH5q0jKWvM`）

| ファイル | 内容 |
| --- | --- |
| `南万騎が原_売り出し_YYYY-MM-DD` | レインズからの週次エクスポート（人が置く） |
| `スナップショット_YYYY-MM-DD` | 取り込んだ生データ |
| `台帳_listings_YYYY-MM-DD` | 売り出し事例の台帳（売出中も掲載終了も残す） |
| `台帳_events_YYYY-MM-DD` | 週ごとの出来事（新規掲載 / 価格改定 / 掲載終了） |
| `台帳_price_history_YYYY-MM-DD` | 価格の観測履歴 |
| `台帳_contracts_YYYY-MM-DD` | 成約事例 |

**毎週「新しい版を足す」追記方式**です。既存ファイルの上書き・削除は行いません。
最新版を見れば現状が分かり、古い版を見れば任意の時点に戻せます。

ドライブのコネクタはファイルの**新規作成と読み取りはできますが、既存ファイルの内容更新ができません**
（`update_file` はタイトルと親フォルダの変更のみ）。版を重ねる方式はこの制約に合わせたものでもあります。

セッション内の作業ファイル（`data/*.csv`, `reports/`）は毎回ドライブから復元される一時的なものです。

## 週次スナップショットのCSV形式

収集側は、出どころが何であれこの18列に正規化して出力します。

```
source,source_id,url,mansion_name,address,station,walk_min,price_man,layout,
area_m2,balcony_m2,floor,floors_total,built_ym,units_total,management_fee,repair_fund,remarks
```

- `price_man` … 価格（**万円**単位）
- `area_m2` … 専有面積（m²）
- `built_ym` … 築年月（`2007年3月` / `2007/03` などを解釈）
- `source` … 出どころの名前。`source_id` があれば同一物件の追跡に使い、無ければ
  マンション名・間取り・面積・所在階から同一性を判定します
- `source` は**掲載終了の判定範囲**でもあります。あるソースを含まないスナップショットを
  取り込んでも、そのソースの物件が誤って掲載終了にされることはありません

見本は `samples/snapshot-sample.csv`（テスト用のダミー行です）。

## 使い方

```bash
# 週次スナップショットを取り込む（差分判定と蓄積はここで行われる）
python3 scripts/mansion_track.py ingest data/snapshots/inbox.csv --date 2026-09-07

# 週次レポート（Markdown）
python3 scripts/mansion_track.py report --date 2026-09-07

# 一覧ビュー（HTML）
python3 scripts/mansion_track.py view

```

## 収集ルート

### 成約事例 — 国土交通省「不動産情報ライブラリ」API（自動）

実際の成約価格が四半期ごとに公開されます。APIキーは無料で申請でき、再利用も認められています。
`gas/MansionWatcher.gs` の `fetchContractsIfNewQuarter_()` が横浜市旭区（市区町村コード `14106`）を
取得し、南万騎が原駅圏の町名（`万騎が原` `さちが丘` `柏町` `善部町` `今川町` `南希望が丘`
`中希望が丘` `大池町` ／ スクリプトプロパティ `DISTRICTS` で変更可）で絞り込みます。

公表は数か月遅れるため、毎回直近5四半期を見て未取得分だけを足します。

> エンドポイントとパラメータ名は公式ドキュメントで最新版を確認してください。

### 売り出し事例 — レインズ等からの週次エクスポート（半自動）

**レインズには売り出し中の物件が原則すべて登録されている**ため、「南万騎が原駅利用の中古マンション
すべて」を追うには、ポータルサイトを見て回るよりレインズを起点にするのが確実です。
週に1回エクスポートし、上の18列に整えて取り込みます。

不動産ポータルサイト（SUUMO・LIFULL HOME'S・at home 等）の自動巡回は、
各社の利用規約で禁止されている場合があります。恒常的な自動収集の手段としては採用していません。

## 実行環境についての注意

Claude のセッションからは不動産サイト・レインズ・国交省いずれにも接続できません
（組織の外部通信ポリシーにより 403 で拒否されます）。
そのため**収集は Google Apps Script 側**で行い、Claude は蓄積されたデータの
集計・レポート・一覧化を担当する分担にしています。

## 週次の運用（レインズ ＋ Claude 週次ルーティン）

収集元にレインズ、報告に Claude の週次ルーティンを使う構成です。
毎週やっていただくのは **1. のエクスポートだけ** で、あとは自動で進みます。

### 1.（人）レインズから週次エクスポート

南万騎が原駅を最寄りとする中古マンションの売出中物件を検索してエクスポートし、
ドライブのフォルダ「南万騎が原 マンション台帳」に置きます。

- ファイル名は **`南万騎が原_売り出し_YYYY-MM-DD`**
- 日付は**エクスポートした日**。ルーティンはこの日付をスナップショットの基準日に使います
- **形式は問いません。PDF でも Google スプレッドシートでも構いません。**
  レインズの出力はPDFになることが多いので、そのまま置いていただければ読み取ります
- 列や項目は元のままで構いません。18列への正規化はルーティン側で行います

> ドライブのコネクタが読めるのは PDF・Google スプレッドシート・Excel・Word などです。
> **素の `.csv` ファイルだけは読めません**ので、CSVで出力した場合は
> ドライブ上で Google スプレッドシートに変換してください
> （右クリック →「アプリで開く」→「Google スプレッドシート」）。

### 2.（自動）毎週月曜 8:20 JST

Claude のルーティン「南万騎が原 マンション台帳 週次更新」
（`trig_01RGEj5roXeMcPWJbCQwZdf8`）が起動し、

1. ドライブから前回までの台帳（各 `台帳_*` の最新版）を読み込む
2. 未取込のエクスポートを探す（PDFならページを読み取って項目を抽出）
3. 18列に正規化し、`ingest` で前週との差分を判定
4. `report` と `view` を生成
5. 更新後の台帳を**新しい版として**ドライブに追加（既存ファイルは触らない）
6. 一覧ページ（Artifact）を同じURLに更新
7. 今週の新規／価格改定／掲載終了をまとめて報告

新しいエクスポートが無かった週は、**何も取り込まず・何も作らず・何も消さず**、
「今週は未着」とだけ報告して終わります。飛ばした週があっても、
次にエクスポートが届いた時点でその間の差分がまとめて判定されます。

### 週の飛びについて

差分は「前回取り込んだスナップショット」との比較です。2週飛ばすと、その2週の間に
出て消えた物件は捕まえられません。掲載終了の検知精度を保つため、
エクスポートは毎週続けるのが理想です。

### ルーティンの方式について

このルーティンは**既存のセッションを起こす方式**です（営業日報のまとめメールと同じ方式）。
新規セッションを毎回立てる方式では Google ドライブのコネクタを引き渡せず、
エクスポートを読めないためです。

曜日・時刻を変えたい場合や、ドライブではなくメール添付で渡したい場合は言ってください。
