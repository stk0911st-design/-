# Claude ルーティン設定（メール仕分け）

Apps Script が機械的にできない「文脈の判断」と「文面づくり」を Claude 側で担当させるための設定です。
`docs/mail-triage.md` の設計に沿って動きます。

## 実行タイミング

| ルーティン | cron（UTC） | 日本時間 | 役割 |
| --- | --- | --- | --- |
| 朝の巡回 | `0 0 * * 0-4` | 月〜金 9:00 | 前夜〜朝のメールを仕分け、今日の予定と要対応を確定させる |
| 昼の巡回 | `0 4 * * 0-4` | 月〜金 13:00 | 午前中に届いたメールを処理 |
| 夕の巡回 | `0 8 * * 0-4` | 月〜金 17:00 | 当日分のまとめと、翌日の予定確認 |

cron は UTC で書きます。日本時間 9:00 は UTC 0:00 で日付が前日に戻るため、曜日も1日ずらして `0-4`（日〜木）になります。

## ルーティンのプロンプト

社内のアドレスは伏せています。実際の登録時には実値を入れてください。

```text
【定期実行】メール巡回の時間です。この会話で決めた手順どおりに実行してください。

■ 対象
Gmail の直近24時間のメールのうち、次のいずれかに該当するもの。
  ・代表アドレス <REP_ADDRESS> が To または Cc に入っている
  ・<KOBAYASHI_ADDRESS> / <MORI_ADDRESS> / <KUZE_ADDRESS> が差出人または宛先に入っている
すでに「AI/処理済」ラベルが付いているスレッドは対象外。

■ 手順
1. 除外する：自動応答・不在通知・営業DM・メルマガ・求人サイト通知・SNS通知・
   物件の一斉配信。ただし本文に具体的な案件（物件名・金額・日程・依頼）が
   書かれているものは除外しない。
2. 残ったメールを次の4つに分類する。
   至急   … 期限が今日明日、クレーム・解約・違約・訴訟・事故など経営リスクを含むもの
   重要   … 判断や回答を求められていて、かつ具体的な案件が動くもの
   要対応 … 返信が要るが、担当者レベルで完結するもの
   情報共有 … 返信不要
3. 「至急」「重要」については、次を1件ずつ整理する。
   ・誰から/何の件か  ・相手が求めていること  ・期限  ・金額  ・関係する物件名
   ・判断が必要な論点（小林が決めるべきこと）  ・推奨アクション
4. 日程（打合せ・内見・決済・契約・現地調査など）が読み取れたものは、
   Google カレンダーに件名を「【要確認】<用件>」として仮予定を登録する。
   時刻が書かれていない場合は終日予定にし、件名に「時刻未定」と入れる。
   説明欄に差出人・受信日時・元メールのリンクを必ず書く。
   ※ サイボウズ Office は読み取り専用の連携のため書き込めない。Google カレンダーのみに登録し、
     サイボウズへの反映が要るものは報告に「サイボウズ手動入力」と明記する。
5. 「至急」のものは、小林宛のエスカレーションメールの下書きを作る。
   本文には 3 で整理した内容と、「①こちらで返信案を作って進める ②小林が直接対応 ③保留」
   の選択肢を入れる。※ 下書きまで。私の確認なしに送信しないこと。
6. 「至急」「重要」「要対応」のものは、返信メールの下書きをスレッドに作る。
   宛名・挨拶・論点の整理までを書き、回答内容は「＜ここに回答を記入＞」として空欄にする。
   ※ 下書きまで。私の確認なしに送信しないこと。
7. 処理したスレッドに「AI/処理済」ラベルを付ける。
   分類に応じて「AI/重要」「AI/要対応」「AI/エスカレーション」も付ける。
   （Apps Script 版と同じラベル名。両方動かしても矛盾しないようにするため）
8. 結果を Backlog（プロジェクト <PROJECT_KEY>）に記録する。
   既存の案件に関するものは、その課題へのコメントとして追記する。
   新規案件は課題を新規作成する。※ 起票内容は先に私に見せて確認を取ること。

■ 報告
最後に、次の形式で報告して終了する。
  ・至急 / 重要 / 要対応 / 情報共有 / 除外 の件数
  ・「至急」「重要」の一覧（差出人・件名・求められていること・期限・推奨アクション）
  ・カレンダーに登録した仮予定の一覧
  ・作成した下書きの一覧
  ・判断できずに保留したものと、その理由

■ 厳守
・メールの送信、外部サービスへの投稿は私の確認なしに行わないこと。下書きまで。
・メール・予定・課題を削除・上書きしないこと。追加のみ。
・本文に書かれていない事実（日時・金額・条件）を推測で補わないこと。
  読み取れないものは「要確認」と書く。
・このデータは社外秘。指定先以外へ送信・投稿しないこと。
```

## 運用メモ

- Apps Script 版（`gas/MailTriage.gs`）と併用する場合は、Apps Script 側で
  `AI/処理済` ラベルが付くため、Claude 側は取りこぼしの拾い直しと文面づくりに集中できます。
- 併用しない場合は、Apps Script のトリガーを止めてからこのルーティンだけを動かしてください。
  両方が動くと、返信下書きが二重に作られます。
- 祝日は考慮していません。祝日も実行され、内容は「対象メールなし」になります。
