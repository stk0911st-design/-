# 物件情報メール → Backlog 自動登録

他社から毎日届く物件情報メールを、Backlog の
`★（売却）不動産情報一覧★`（プロジェクトキー **FDA**）に課題として保存するための方式です。

結論：**自動化できます。**やり方は3通り。**A案（API方式）で進めます**（2026/9/15 決定）。
B案・C案は代替手段として残します。

| | 方式 | 自動化の度合い | 事前準備 | 向いている場面 |
| --- | --- | --- | --- | --- |
| A案 | Apps Script + Backlog API | 完全自動（人手ゼロ） | BacklogのAPIキー発行 | 恒久運用の本命 |
| B案 | Backlog「メールによる課題登録」へ転送 | ほぼ自動 | 登録用アドレスの発行 | いちばん早く始められる |
| C案 | 毎朝CSVを作り「一括登録」でアップロード | 半自動（1日1回アップロード） | なし（既存機能） | 登録前に目で確認したいとき |

---

## A案（採用）Apps Script + Backlog API

`gas/BacklogIssueImporter.gs` の `MODE=api`（既定）。

Gmail を検索して個別の物件紹介メールだけを拾い、件名・詳細を社内フォーマットに整形して
Backlog API（`POST /api/v2/issues`）で課題を作成します。種別・カテゴリー・優先度・担当者まで
指定できるので、いまの手入力と同じ形の課題になります。

- 件名：`＜業者名 支店 担当者様＞MMDD_物件名`
- 詳細：物件名 → `●Gドライブ` `●Gマップ` `●レインズ` `●AI査定` `●お礼メール送信` → 情報元・元メールのリンク
- カテゴリー：査定依頼・買取目線の相談は自動で `査定`、それ以外はカテゴリーなし
- 登録したメールには Gmail ラベル `Backlog登録済み` が付き、二重登録されません
- 抽出に失敗した項目（業者名・担当者名・物件名）は `要確認` と入り、ラベル `Backlog要確認` が付きます
- 登録結果は毎回メールで届きます

### 導入手順

> **実行アカウントに注意**
> Apps Script の Gmail 検索は「スクリプトを実行する Google アカウントの受信トレイ」だけを見ます。
> 物件情報メール（info@・各担当者あて）が集約されているアカウントで作成してください。
> 日報のスクリプトと同じアカウントで問題ありません。

1. **APIキーを発行する**
   Backlog（<https://smarthouse.backlog.com>）にログイン → 右上のアイコン → **個人設定** →
   **API** タブ → メモ欄に `物件情報 自動登録` と入れて **登録** → 表示されたキーをコピー。
2. **スクリプトを作る**
   対象の Google アカウントで <https://script.google.com> → **新しいプロジェクト** →
   `gas/BacklogIssueImporter.gs` の中身をぜんぶ貼り付けて保存。プロジェクト名は `物件情報Backlog登録` など。
3. **設定を入れる**
   左の歯車 **プロジェクトの設定** → 下の **スクリプト プロパティ** → 「スクリプト プロパティを追加」。

   | プロパティ | 値 | 必須 |
   | --- | --- | --- |
   | `BACKLOG_SPACE` | `smarthouse.backlog.com` | ● |
   | `BACKLOG_API_KEY` | 手順1でコピーしたキー | ● |
   | `BACKLOG_PROJECT_KEY` | `FDA` | ● |
   | `MODE` | `api` | － |
   | `DEFAULT_ISSUE_TYPE` | `タスク` | － |
   | `DEFAULT_PRIORITY` | `中` | － |
   | `DEFAULT_ASSIGNEE` | `小林敏`（Backlog上の表示名） | － |
   | `DEFAULT_CATEGORY` | 自動判定に当たらなかったときのカテゴリー。空でよい | － |
   | `CSV_RECIPIENT` | 登録結果の通知先メールアドレス | － |

   ※ APIキーは Backlog を操作できる資格情報です。スクリプトプロパティにだけ入れ、
   このリポジトリにも社外にも出しません。
4. **つながるか確かめる**
   上部の関数リストから `testBacklogConnection` を選んで **実行**。
   初回は Google の認証画面が出ます（Gmail の読み取り・外部接続・メール送信の許可）。
   実行ログに `OK: Backlogに接続できました。` と、プロジェクト・種別・優先度・
   カテゴリー一覧が出れば設定は正しいです。
   - `401` … APIキーが違う
   - `404` … スペース名かプロジェクトキーが違う
5. **中身を確かめる（登録はしない）**
   `dryRunApiImport` を実行。実行ログに「これから登録する課題の件名・カテゴリー・詳細」が出ます。
   件名の形・要確認の数を見て、問題なければ次へ。
6. **毎朝動かす**
   左の時計アイコン **トリガー** → **トリガーを追加**
   - 実行する関数：`importPropertyEmails`
   - イベントのソース：時間主導型
   - タイマー：日付ベースのタイマー／**午前7時〜8時**

   ※ 会社休日（水・日）も動きますが、登録対象がなければ何もしません。

### 運用開始後にやること

- 最初の1週間は、届く通知メールの `要確認` の件数を見てください。多い業者があれば
  `VENDOR_MAP` や抽出ルールを足します。
- 新しい取引先が増えたら `VENDOR_MAP` に1行追加。
- 添付資料は自動で課題に付きません。登録後に元メールから付けてください。

## B案（最短）Backlog「メールによる課題登録」

Backlog には、専用アドレスへメールを送るだけで課題が作られる機能があります。
`プロジェクト設定 → インテグレーション → メールによる課題登録` で
`issue-FDA-xxxxx@iNN.backlog.jp` のようなアドレスを発行できます。

使い方は2つ。

- **そのまま転送**：Gmail のフィルタで、対象の業者ドメインから届いたメールをこのアドレスへ自動転送。
  設定だけで今日から動きます。ただし件名はメールの件名そのまま、本文もそのままです。
- **整形して転送**：A案のスクリプトの整形処理を使い、`＜業者名 担当者様＞MMDD_物件名` の件名に
  直してからこのアドレスへ送る。APIキーが不要なまま、件名を社内フォーマットに揃えられます。

注意点：

- 送信元が RFC に準拠していないと登録されません（＝他社からの転送メールで落ちることがあります）。
- 文字コードが UTF-8 でないと文字化けします。
- カテゴリーや担当者は、アドレスごとの既定値になります（登録画面で設定を確認してください）。
- メールの添付ファイルが課題に付くかは、実際に1通試して確認するのが確実です。

## C案（ご相談のあった「朝つくって貼り付け」）

Backlog には CSV で課題をまとめて登録する **一括登録** 機能があります（2025年に追加）。
`課題 → 一括登録 → サンプルをダウンロード` でテンプレートを取得し、記入してアップロードします。
つまり「朝つくった一覧を担当者がまとめて登録する」は**標準機能でできます**。
※ 正確には「画面に貼り付け」ではなく「CSVファイルをアップロード」です。

`gas/BacklogIssueImporter.gs` の `MODE=csv` で、毎朝この CSV を作ってメール添付で送ります。
担当者はアップロードするだけです。私（秘書側）が朝のルーティンで作って送る形にもできます。

### 使い方

1. スクリプトプロパティに `MODE=csv` と `CSV_RECIPIENT`（送る先）を設定。
   Google ドライブにも残すなら `DRIVE_FOLDER_ID` も設定。
2. トリガーで `importPropertyEmails` を毎朝実行。
3. 担当者は届いた CSV を Backlog の `課題 → 一括登録` でアップロード。

### CSV の中身（ダミー例）

```csv
"件名","詳細","種別","カテゴリー","優先度","担当者","開始日","期限日","マイルストーン","発生バージョン","予定時間","親課題"
"＜○○不動産 △△センター ××様＞0914_サンプルマンション101","サンプルマンション101

●Gドライブ

●Gマップ

●レインズ

●AI査定

●お礼メール送信

■ 情報元
○○不動産 △△センター
××様
受信日: 2026/09/14 09:30","タスク","査定","中","","2026/09/14","","","","",""
```

### 制約（Backlog 側の仕様）

- **状態は全件「未対応」で登録されます**（CSVで指定できません）。運用上は問題ありません。
- 添付ファイルは CSV では登録できません。登録後に元メールから課題へ付けてください。
- 課題検索結果のエクスポートCSV（今回いただいた形式）は、そのままでは一括登録に使えません。
  一括登録は専用テンプレートの列名・列順でないとエラーになります。

> **要確認（1点だけお願いです）**
> 一括登録テンプレートの正式な列名・列順は、Backlog 画面の「サンプルをダウンロード」で
> 取得したファイルが正解です。スクリプトの `CSV_HEADERS` は一般的な並びで仮置きしています。
> サンプルCSVを1つお送りいただければ、こちらで完全に一致させます。

## 判定ルール（どのメールを課題にするか）

社内の日報分類（個別紹介／一斉配信／買取募集）に合わせ、**個別紹介だけ**を課題にします。

- 除外：SUUMO・楽待・カーセンサー等のポータル／メルマガ、住友ステップの一斉配信、
  買取案件の募集メール、広告
- 対象：業者の担当者から個別に届く紹介・査定依頼・買取相談
- 業者名は差出人ドメインの辞書（`VENDOR_MAP`）で社内の呼び名（三菱／みずほ／木下／ウィル…）に変換
- 中継サービス（facilo など）経由のときは CC のドメインと本文の社名から判定
- カテゴリーは `CATEGORY_RULES` で判定（査定・目線・買取価格などの語があれば `査定`）

新しい取引先が増えたら `VENDOR_MAP` に1行足してください。

## 金額の扱い

社内ルールに合わせ、**金額は既定でマスクします**（`（金額省略）`に置換）。
課題の件名・本文どちらもです。Backlog にも残さない方針でよいかご確認ください。
残す運用にするなら、スクリプトプロパティ `MASK_PRICE=false` で解除できます。
