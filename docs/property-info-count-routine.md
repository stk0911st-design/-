# 不動産情報 日次件数レポート（毎日21時）

その日に届いた不動産情報が何件だったかを、毎日 21:00（JST）にメールで報告します。

| 項目 | 値 |
| --- | --- |
| cron（UTC） | `0 12 * * *` |
| 日本時間 | 毎日 21:00 |
| 起動モード | 既存セッションを継続（Gmail のコネクタを保持しているため） |
| 宛先 | 小林（設定値として管理） |
| 集計範囲 | 当日 JST 0:00 〜 実行時点 |
| 蓄積 | 過去のレポートメール自身をデータの保管場所とする（後述） |

日本時間 21:00 は UTC 12:00 で、日付は戻りません。曜日指定なし＝毎日実行です。
（朝8時の営業日報とは違い、曜日をずらす必要はありません）

## 数え方

受信メールのみを対象とし、自社の送信メール・下書きは数えません。

### 1. 個別紹介（仕入れ候補）★本命の数字

仲介会社・業者から、自社または社員宛に、**具体的な物件を名指しで**紹介してきたもの。
物件名または所在地が特定できるものだけを数えます。
既存案件に関する個別連絡（資料送付・進捗報告・見送り回答）もここに含めます。

### 2. 一斉配信の物件情報

業者の物件一覧の一斉メール、ポータルサイトの新着通知。

### 3. 買取募集・情報依頼（参考値）

「物件情報をください」「買い取ります」という営業。物件情報そのものは入っていません。

### 数えないもの

求人サイト、SNS通知、Backlog の通知、金融機関の自動応答、
不動産と無関係なメルマガ（自動車・アパレル・飲食・旅行など）、
業務ツールやセミナーの営業、セキュリティ通知、請求・決済通知、交通運行情報。

## メールの中身

1. 本日の件数表（3分類）
2. **累計の表**：今週 / 今月 / 通算 × 3分類
3. **今月の情報元ランキング**（個別紹介ベース、上位10社）
4. 本日の個別紹介の内訳：受信時刻 / 会社名・担当者 / 物件名または所在地 / 価格・目線 / 何を求められているか
   （返答や対応が必要な行は背景に色を付ける）
5. 注記
6. 集計用データブロック（後述）

- 本文に書かれていない事実（価格・所在地・面積）は推測で補わず「記載なし」と書く
- 0件でも「本日、個別の物件紹介はありませんでした」と明記して必ず送信する

## 蓄積のしくみ

件数を日々ためて累計や情報元別の集計を出すには、データの保管場所が要ります。
**過去のレポートメール自身を保管場所**にしています。

各レポートの末尾に、翌日以降が読み取るための集計用データブロックを入れます。

```
[DATA] 2026-09-03 | 個別=15 | 一斉=11 | 買取=12
[SRC] 会社名=2, 会社名=2, 会社名=1, ...
```

翌日の実行では、Gmail を `subject:【不動産情報】` で検索して過去のレポートを読み、
このブロックを集めて累計と情報元ランキングを作ります。

- 同じ日付のブロックが複数見つかった場合は、最も新しいものだけを使います（重複加算しない）
- ブロックが1件も読めなかった場合は、累計欄に「過去データを読み取れませんでした」と書き、
  本日分だけを送ります。累計を推測で埋めることはしません
- 情報元は会社名で名寄せします（担当者違いは同じ会社として1社にまとめる）

**レポートメールを削除すると、その日のデータが失われます。**
メール本文にもその旨を記載しています。

### なぜスプレッドシートやリポジトリに置かないか

| 保管先 | 判断 |
| --- | --- |
| Google スプレッドシート | **不可**。現在つながっている Drive の機能はファイルの作成と読み取りだけで、既存シートへの行の追記ができない |
| このリポジトリ | **採用せず**。取引先名・担当者名・物件・価格を含むため、社内情報を外部に置かない方針に反する |
| レポートメール自身 | **採用**。データが自社のメールボックスの外に出ない。小林が履歴をそのまま読み返せる |

将来 Apps Script（`gas/MailTriage.gs`）を導入し `LOG_SPREADSHEET_ID` を設定すれば、
社内のスプレッドシートに蓄積する方式へ移行できます。その場合はグラフ化も可能になります。

## 判断が分かれる点（運用しながら調整する）

**BCC の一斉配信だが、具体的な物件を1件だけ名指ししているもの**の扱いです。
「弊社販売物件のご紹介」「新規物件情報です」といった、宛名は自社宛だが
実際には多数の業者へ同報されているメールが該当します。

現在は **物件が特定できるものは「個別紹介」に入れる** 方針にしています。
仕入れ候補として検討しうる情報だからです。
これを「一斉配信」に寄せると、個別紹介の件数は3〜4割減ります。
どちらの数字を KPI にするかは、運用しながら決めてください。

## 2026年9月3日(木)の実測値

導入前に、実際の受信メール約136スレッドを全件確認した結果です。

| 分類 | 件数 |
| --- | --- |
| 個別紹介（仕入れ候補） | 15 |
| 一斉配信の物件情報 | 11 |
| 買取募集・情報依頼 | 12 |
| 合計（不動産関連） | 38 |

不動産と無関係なメールが約100件あり、全体の7割以上を占めていました。
この比率であれば、件数の推移は仕入れ環境の指標として使えます。

## 今後の拡張候補

- 情報元ランキングを「件数」だけでなく「成約・買付に至った率」でも出す
- 週次・月次の推移グラフ（スプレッドシート移行後）
- 情報元別に、前月比で件数が落ちている会社を検出して知らせる
