# ListingTracker（Apps Script 版）

世田谷区・杉並区・大田区・渋谷区の「土地」「戸建て」売り出し物件をSUUMOから
毎日取得し、新規件数・消失件数（成約想定）・平均坪単価を集計してメール送信する
Apps Scriptです。設計の背景・限界は `docs/listing-tracker-plan.md` を参照。

## 導入手順

1. 新しいGoogleスプレッドシートを作成する（例：「売り出し物件トラッカー」）。
   ※このスプレッドシートに `在庫スナップショット` `日次サマリ` `月次集計` の
   3つのシートが自動で作られます。
2. 「拡張機能 → Apps Script」を開き、`ListingTracker.gs` の内容を貼り付ける。
3. 「プロジェクトの設定 → スクリプト プロパティ」に次を追加する。

   | プロパティ | 値 |
   | --- | --- |
   | `RECIPIENT` | 送信先メールアドレス（例：小林様のアドレス） |
   | `CC` | （任意）CCアドレス。カンマ区切り |

4. **必ず本番実行の前に** `selfTestOneCategory('setagaya', 'land')` を実行し、
   実行ログ（表示 → ログ）で次を確認する。
   - HTTPステータスが200であること
   - 「1ページ目で抽出できた物件数」が、実際にブラウザで
     `https://suumo.jp/tochi/tokyo/sc_setagaya/` を開いたときの掲載件数と
     大きくズレていないこと
   - サンプルの価格・面積が実際の物件と一致していること
   - ズレている場合は、`parseListingsFromHtml_` の正規表現を、
     実際のHTML構造に合わせて調整する（クラス名の変更などが原因）
5. 8種別（4区 × 土地・新築一戸建て・中古一戸建て。実際は `land` `house_new`
   `house_used` の3カテゴリ）すべてを確認したい場合は `selfTestAllCategories()`
   を実行する。
6. `previewListingMail` を実行して、メール文面を確認する（ダミー数値・実送信あり）。
7. 問題なければ「トリガー → トリガーを追加」で次を設定する。
   - 実行する関数: `runDailyListingCheck`
   - イベントのソース: 時間主導型
   - 日付ベースのタイマー: 午後6時〜7時（18:00 JST 想定）

## 動作

- 4区 × 3カテゴリ（土地・新築一戸建て・中古一戸建て）を毎回クロールする。
- 各カテゴリのページを自動でページ送りしながら物件IDを集め、前回実行時の
  一覧と突き合わせて新規・消失を判定する（詳しくは `ListingTracker.gs` 冒頭のコメント）。
- 「消失件数」は成約の確定値ではない。掲載終了・再掲載なども含まれ得る
  （`docs/listing-tracker-plan.md` 参照）。
- `月次集計` シートは当月分を区・種別ごとに1行、日々上書き更新する。

## 運用メモ

- SUUMOのページ構造が変わると抽出件数が0件になることがある。
  0件が続く場合は `selfTestOneCategory` で状況を確認すること。
- 1回の実行で数十〜百数十ページをクロールするため、Apps Scriptの実行時間
  （個人アカウントは最大6分）に収まらない場合は `LT_MAX_PAGES` や
  `LT_BATCH_SIZE`（`ListingTracker.gs` 冒頭）を調整するか、区・カテゴリごとに
  実行を分割するトリガー構成に変更する。
