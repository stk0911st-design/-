# DailyReportMailer（Apps Script 版）

日報カウンターのスプレッドシートに入力された内容を集計して、
指定アドレスへメール送信する Apps Script です。3つの送信タイミングがあります。

## 導入手順

1. 日報カウンターのスプレッドシートを開き、「拡張機能 → Apps Script」。
   （スプレッドシートの編集権限が必要です）
2. `DailyReportMailer.gs` の内容を新しいスクリプトファイルに貼り付ける。
3. 「プロジェクトの設定 → スクリプト プロパティ」に次を追加する。

   | プロパティ | 必須 | 値 |
   | --- | --- | --- |
   | `RECIPIENT` | 必須 | 送信先メールアドレス（小林様宛） |
   | `CC` | 任意 | 夜のまとめメールに固定でCCするアドレス。カンマ区切り |
   | `SPREADSHEET_ID` | 条件付き | 別ファイルのスプレッドシートを対象にする場合のみ必須 |
   | `STAFF_EMAILS` | 任意 | 担当者名→メールアドレスのJSON。例: `{"山田":"yamada@example.com"}`。朝のリマインドと、夜のまとめメールの全員CCに使う |
   | `BROADCAST_CC` | 任意 | `true` にすると、夜のまとめメールを `STAFF_EMAILS` の全員にもCCする（既定は送らない＝`false`） |
   | `REPORT_APP_URL` | 任意 | 朝のリマインドに載せる「日報カウンターを開く」ボタンのリンク先 |

   ※ `STAFF_EMAILS` / `BROADCAST_CC` / `REPORT_APP_URL` は、個人の勤務・入力状況を
   全担当者に共有する運用を伴います。社内で運用方針（誰に何を共有するか）を
   決めたうえで設定してください。未設定のままなら、該当機能は動きません
   （朝のリマインドは送信スキップ、夜のまとめは小林様のみへの送信になります）。

4. 次の3つを実行して、実行ログで文面を確認する（送信はされません）。
   - `previewDailyReportMail`（従来の朝まとめ）
   - `previewMorningReminderMail`（朝9:30のリマインド）
   - `previewEveningReportMail`（夜20:00のまとめ）
5. 問題なければ「トリガー → トリガーを追加」で次の3本を設定する。

   | 実行する関数 | タイミング |
   | --- | --- |
   | `sendDailyReportMail` | 時間主導型・日付ベース・午前8時〜9時（土日は関数側でスキップ） |
   | `sendMorningReminderMail` | 時間主導型・日付ベース・午前9時〜10時 |
   | `sendEveningReportMail` | 時間主導型・日付ベース・午後8時〜9時 |

## 動作

### `sendDailyReportMail`（午前・前営業日分のまとめ、小林様宛）

- 火〜金：前日1日分
- 月：前週の金・土・日の3日分
- 土日：何もしない
- 対象日に入力が0件でも「入力なし」のメールを送信します。

### `sendMorningReminderMail`（毎朝9:30・担当者へ個別送信）

- `STAFF_EMAILS` に登録された担当者ひとりずつに、本日分の入力を促すメールを送ります。
- `REPORT_APP_URL` を設定していれば、メール内にボタン（リンク）を入れます。
- 出勤予定を管理する仕組みが現状ないため、`STAFF_EMAILS` の全員に送ります
  （出勤日だけに絞りたい場合は、別途シートを用意する改修が必要です）。

### `sendEveningReportMail`（毎晩20:00・当日分のまとめ、小林様宛）

- 当日分の入力状況を集計して小林様へ送ります。`BROADCAST_CC` が `true` の場合、
  `STAFF_EMAILS` の全員をCCに追加します（＝全員が全員分の入力状況を見られる状態になります）。
- 未入力者がいる場合、注意文と、採用状況にふれる一文を本文に追加します。
  文言は `DailyReportMailer.gs` の `buildEveningHtml_` にあります。実際に送る前に、
  文面が社内の意図どおりか必ず確認してください。
