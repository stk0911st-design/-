# 業務自動化

株式会社スマートハウスの業務を自動化するスクリプトとルーティン設定をまとめたリポジトリです。

| 自動化 | 内容 | ドキュメント |
| --- | --- | --- |
| 営業日報 まとめメール | 日報カウンターの入力を翌営業日の朝にまとめて送信 | 下記 |
| メール自動仕分け | 代表・役員宛メールの仕分け／予定登録／エスカレーション／返信下書き／記録 | [`docs/mail-triage.md`](docs/mail-triage.md) |
| 不動産情報 日次件数 | その日届いた不動産情報の件数を毎日21時にメール報告 | [`docs/property-info-count-routine.md`](docs/property-info-count-routine.md) |
| 査定未返答アラート | 物件情報の入手から3営業日以内に査定を返していないものを毎営業日9時に通知 | [`docs/assessment-alert-routine.md`](docs/assessment-alert-routine.md) |

※ スプレッドシートID・宛先アドレス・API キーなどはこのリポジトリには置かず、
実行環境側（Claude のルーティン設定、または Apps Script のスクリプトプロパティ）で管理します。

---

## 営業日報 まとめメール自動化

営業日報アプリ（Google Apps Script + スプレッドシート「日報カウンター」）に入力された内容を、
翌営業日の朝に担当者へまとめてメール送信するための自動化です。

### 仕様

| 項目 | 内容 |
| --- | --- |
| 入力元 | 日報カウンター（GASアプリ）の記録先スプレッドシート |
| 集計対象 | 「更新日時」が対象日に該当する入力レコード |
| 対象日 | 火〜金の配信＝前日1日分／月曜の配信＝前週の金・土・日3日分 |
| 配信タイミング | 平日 毎朝 8:00（JST） |
| 宛先 | 社内の指定アドレス1件（設定値として管理） |
| 送信方法 | 自動送信 |

### データ構造

スプレッドシートには2つの表があります。

**集計表**

`週開始日 / 担当者 / 架電 / メール / 物件情報取得 / 査定 / 訪問・面談 / 現地調査 / 買付・価格提示 / 契約 / その他 / 合計 / コメント`

**生データ表**（この表を集計に使用）

| 列 | 内容 |
| --- | --- |
| key | `report｜<週開始日>｜<担当者>` |
| value | JSON文字列 |
| 更新日時 | 入力（保存）された日時（JST） |

value の JSON キー対応:

| JSONキー | 日本語 |
| --- | --- |
| call | 架電 |
| mail | メール |
| information | 物件情報取得 |
| assessment | 査定 |
| visit | 訪問・面談 |
| site | 現地調査 |
| offer | 買付・価格提示 |
| contract | 契約 |
| other | その他 |
| memo | コメント |
| staff | 担当者 |
| week | 週開始日 |

#### 注意：カウンターは「週単位の累計値」

日報アプリのカウンターは週ごとの累計値であり、日別の増分ではありません。
そのため「対象日に入力（保存）があったレコードの、その時点の週累計値」をまとめる形になります。
メール本文でもその旨を明記します。

### 実装方式

2通りの実装を用意しています。

#### 1. Claude のルーティン（現在稼働中）

平日 8:00 JST にこのセッションを起こし、スプレッドシートを読み取って集計・送信します。
設定は `docs/routine-prompt.md` を参照。

- 長所：導入済みで追加作業なし。文面を柔軟に調整できる。
- 短所：Claude 側のセッション／コネクタ状態に依存する。

#### 2. Google Apps Script（`gas/DailyReportMailer.gs`）

スプレッドシート側に時間主導トリガーを設定して送信する方式。
Claude に依存せず動き続けるため、恒久運用にはこちらが確実です。

導入手順は `gas/README.md` を参照。

## メール自動仕分け・予定登録・エスカレーション

代表アドレスおよび小林・森・久世宛のメールを走査し、営業DM等を除外したうえで、
内容を判定して次を行います。

- 日程が読み取れたメール → Google カレンダーに「【要確認】」付きの仮予定を登録
- 至急と判定したメール → 代表（小林）宛のエスカレーション文を作成し、指示を仰ぐ
- 要対応と判定したメール → スレッドに返信下書きを作成（送信はしない）
- 結果 → ログシート／Backlog／kintone に記録し、夕方にまとめを送る

**メールの送信と外部への投稿は、既定では行いません。**すべて下書きまでで止まります。

導入前に読むもの：

- [`docs/mail-triage.md`](docs/mail-triage.md) … 設計・判定基準・環境の制約・導入手順
- [`docs/mail-triage-routine.md`](docs/mail-triage-routine.md) … Claude ルーティン版のプロンプト
- [`gas/README.md`](gas/README.md) … Apps Script 版の設定項目

### 環境の制約（要確認事項）

| 項目 | 状況 |
| --- | --- |
| サイボウズ Office への予定登録 | **現状できません。** Google カレンダーへ読み取り専用で取り込まれているだけのため、書き込みには別途 API 連携が必要です |
| 各人のメールボックスへの直接アクセス | できません。代表アドレス宛／CC に集約されている分を対象にしています |
| Backlog / kintone への登録 | API キーの設定が必要です。未設定ならスキップされます |

詳細と対処案は [`docs/mail-triage.md`](docs/mail-triage.md) の「1. 前提として確認した事実」を参照してください。

## 不動産情報 日次件数レポート

その日に届いた不動産情報が何件だったかを、毎日 21:00（JST）にメールで報告します。
「個別紹介（仕入れ候補）／一斉配信／買取募集」の3分類で数え、
個別紹介については会社・物件・価格の内訳も載せます。

Claude のルーティンとして稼働します。設定と数え方は
[`docs/property-info-count-routine.md`](docs/property-info-count-routine.md) を参照。

---

## 査定未返答アラート

物件情報を入手してから3営業日以内に査定を返していないものを検出し、
毎営業日9:00（JST）に代表宛へアラートメールを送ります。該当が0件の日は送りません。

Backlog の API キーが未設定でも、**Backlog の通知メールと Gmail の送信履歴**から
判定しています。詳細は [`docs/assessment-alert-routine.md`](docs/assessment-alert-routine.md) を参照。
